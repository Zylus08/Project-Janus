# PROJECT JANUS v0.54 — KILLER MOVE HEURISTIC SPECIFICATION

**Phase:** Phase 2 — Formal Killer Move Heuristic Specification  
**Date:** 2026-11-05  
**Candidate Engine:** Janus Native N5  

---

## 1. Algorithmic Purpose

The killer move heuristic is based on the principle that if a quiet move causes a beta cutoff in one branch at ply $p$, the same move is very likely to cause a beta cutoff in sibling subtrees at the same search ply $p$. Prioritizing killer moves allows the engine to prove cutoffs earlier in sibling trees without evaluating suboptimal quiet moves first.

---

## 2. Data Structure & Memory Layout

```cpp
constexpr int MAX_PLY = 64;
constexpr int KILLER_SLOTS = 2;

// Static table: 64 plies * 2 slots * 2 bytes = 256 bytes total memory footprint
static uint16_t g_killer_moves[MAX_PLY][KILLER_SLOTS];
```

- **Zero Dynamic Allocation:** Statically allocated in the BSS segment.
- **Sentinel Encoding:** `0` represents an empty slot (no valid chess move encodes to 0 with standard bit packing).
- **Ply Bounds:** Guarded strictly by `ply < MAX_PLY`.

---

## 3. Update Semantics

When a move $m$ searched at tree depth `depth` and distance-from-root `ply` causes a beta cutoff ($alpha \ge beta$):

```cpp
if (g_use_killer_ordering && ply < MAX_PLY) {
    bool is_quiet = (undo.captured_piece == NO_PIECE) && (move_flag(m) != 3);
    if (is_quiet) {
        if (g_killer_moves[ply][0] != m) {
            // Shift primary killer to secondary slot
            g_killer_moves[ply][1] = g_killer_moves[ply][0];
            // Promote new cutoff move to primary slot
            g_killer_moves[ply][0] = m;
        }
    }
}
```

### Invariant Rules:
1. **Quiet Exclusivity:** Captures and pawn promotions are never recorded as killer moves.
2. **Duplicate Suppression:** If move $m$ already occupies slot 0, no update occurs.
3. **Slot Promotion:** A new killer move replaces slot 0, and the previous occupant of slot 0 moves to slot 1. The previous occupant of slot 1 is discarded.
4. **Legality Independence:** Killer moves are ordering hints. They are scored during move ordering only if they are generated by the legal move generator. A killer move from a sibling position that is illegal in the current position is simply ignored.

---

## 4. Score Hierarchy & Integration

In `score_move_for_ordering()`:

```cpp
// 5. Killer Moves (if enabled)
if (g_use_killer_ordering && ply < MAX_PLY) {
    if (m == g_killer_moves[ply][0]) return 90000;
    if (m == g_killer_moves[ply][1]) return 80000;
}
```

### Ordering Justification:
- **Transposition Table Move:** $10,000,000$ (Highest priority).
- **Pawn Promotions:** $800,000 - 900,000$.
- **Tactical Captures (MVV-LVA):** $99,996 - 100,040$.
- **Primary Killer (Slot 0):** $90,000$.
- **Secondary Killer (Slot 1):** $80,000$.
- **History-Scored Quiets:** $1 - 70,000$.
- **Unscored Quiets:** $0$.

Under this configuration:
- Tactical captures are never demoted below quiet killers.
- Primary killers are searched before secondary killers.
- Killers take precedence over general history-scored quiet moves.

---

## 5. Lifecycle & Reset Semantics

- **UCI `ucinewgame`:** Invokes `native_clear_killers()`, resetting all entries to 0.
- **Top-Level `native_search()`:** Clears killers before beginning iterative deepening to prevent cross-position search pollution.
- **Thread Safety:** Single-threaded execution per UCI instance; no thread contention.
