### 3. Architectural Innovations in Janus Classical X12

Candidate X12 completely re-architects the multithreaded search infrastructure:

1. **64-Byte Cache-Line Packed Transposition Table Cluster:**
   * Memory layout: 3 entries $\times$ 16B + 4B `std::atomic_flag` lock + 12B alignment padding = **exactly 64 bytes** (`alignas(64)`).
   * Eliminates all cache-line straddling and false sharing.
   * Yields **1,572,864 entries in 32 MB** (a **50% increase in capacity** over X11's 1,048,576 entries in the same memory budget).
   * Scales concurrent throughput to **33.30 million ops/sec** with 0 data corruptions.

2. **Smart Depth-Preferred Replacement Policy:**
   * Prevents shallow overwrite: On key collision, entries are only overwritten if `depth >= existing.depth - 1`, or `flag == TT_EXACT`, or the entry belongs to an older search age.
   * Best-move backfilling: If a shallower search produces a best move and the existing entry lacks one, the move is updated without clobbering the deeper score.

3. **Zero-Contention Warm History Inheritance:**
   * Upon thread spawning, Worker 0's master history table is snapshotted to helper threads.
   * Helper threads execute move ordering and gravity updates on thread-local memory with zero atomic contention.

4. **Canonical Depth-1 Start & Authoritative Master Root Arbitration:**
   * All threads start at canonical depth 1.
   * Worker 0 is the sole arbiter of the root PV; helper threads populate the shared TT to accelerate Worker 0, completely preventing superficial fail-high bounds from corrupting root move decisions.

5. **Fast-Clock Gating:**
   * For time budgets $< 150$ms, search falls back to single-threaded mode, eliminating thread synchronization overhead and OS scheduler jitter under bullet/blitz conditions.
