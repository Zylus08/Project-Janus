## 3. The 6 Root Causes of Janus H1 Neural Failure

Through 15 systematic experimental phases, Milestone P2.2 identified and isolated the exact causal mechanisms behind H1's playing strength deficit:

### 3.1 Root Cause 1: 4x–10x Centipawn Score Compression
The H1 network was trained exclusively on binary/trinary game outcomes ($z \in \{0.0, 0.5, 1.0\}$) using Binary Cross Entropy (BCE) loss:
$$\mathcal{L}_{\text{BCE}} = - [z \ln \sigma(\hat{y}) + (1 - z) \ln (1 - \sigma(\hat{y}))]$$
Because $49.5\%$ of the 50,978 dataset positions were draws ($z = 0.5$), the BCE gradient strongly penalized extreme logit values. The resulting network logits compressed heavily into the range $[-1.2, +1.2]$.
When mapped to centipawns via $400 \cdot \hat{y}$:
- Queen advantage evaluates to $+203\text{ cp}$ (vs $+867\text{ cp}$ in Classical R1).
- Minor piece advantage evaluates to $+92\text{ cp}$ (vs $+305\text{ cp}$ in Classical R1).
- Pawn advantage evaluates to $+25\text{ cp}$ (vs $+100\text{ cp}$ in Classical R1).

Because evaluation deltas were compressed by $4\times$ to $10\times$, the alpha-beta search saw material advantages as insignificant statistical fluctuations.

### 3.2 Root Cause 2: Uncalibrated +52 cp Side-to-Move Initiative Bias
In symmetrical, completely equal quiet positions, H1 outputs an average evaluation of $+52\text{ cp}$ to $+60\text{ cp}$ in favor of whichever side has the move.
When combined with score compression:
- If White is down a full pawn ($-25\text{ cp}$ in H1's compressed scale) with White to move, the network evaluates:
  $$\text{Eval} = -25\text{ cp} + 52\text{ cp} = +27\text{ cp} \quad (\text{White evaluates as winning!})$$
H1 therefore willingly blundered pawns and allowed tactical sacrifices, believing that possessing the move compensated for lost material.

### 3.3 Root Cause 3: Inverted Piece Valuation Hierarchy
Evaluation of raw piece values in the initial starting configuration revealed that H1's training objective failed to establish monotonic piece values:
- Knight margin: $+174\text{ cp}$
- Rook margin: $+218\text{ cp}$
- Queen margin: $+151\text{ cp}$

In the opening position, H1 valued a Queen **lower than a Knight or a Rook** ($Q < N < R$). Without teacher search scores, the network could not learn the long-term mobility and combinatorial power of the Queen from sparse game outcomes alone.

### 3.4 Root Cause 4: Lack of King Conditioning (DP-PS-768 Feature Limits)
Milestone P2.1 designated its feature schema as "HalfKP-768". Mathematical and empirical audit revealed that this designation was incorrect:
- True HalfKP indexes every piece relative to its king's square: $\text{Feature}(k, p, s) = 64 \times (p \cdot 64 + s) + k$ ($40,960$ features).
- H1's schema indexes pieces purely by piece type and square: $\text{Feature}(p, s) = p \cdot 64 + s$ ($768$ features).
- Moving the friendly king changes *only* the king's single piece-square feature; pawn, knight, bishop, rook, and queen features remain 100% identical.

The architecture was formally reclassified as **Dual-Perspective Piece-Square-768 (DP-PS-768)**. Because the accumulator combines inputs linearly, DP-PS-768 is fundamentally unable to compute bilinear cross-terms representing king shelter, pawn shields, open attacking files, or king confinement.

### 3.5 Root Cause 5: 6x Search Latency Slowdown (Bypassed Incremental Updates)
Profiling the C++ search engine revealed a major architectural bottleneck:
- `r1_search.hpp` called `NNUEEvaluator::evaluate_full(b)` at every leaf node instead of maintaining an incremental accumulator stack along the search path.
- Micro-benchmark timings (20,000 warm evaluations):
  - Classical Evaluation: $1.25\ \mu\text{s}$
  - NNUE Full Evaluation: $7.49\ \mu\text{s}$ ($6.01\times$ slower)
  - Incremental `update_move`: $0.11\ \mu\text{s}$

Under fixed time controls ($5.0\text{s} + 0.05\text{s}$), NNUE H1 was starved of $2$ to $3$ plies of search depth compared to Classical R1, causing terminal tactical blindness in middlegames.

### 3.6 Resolution of the Hybrid H2 Paradox: H2 Degrades R1 by -424 Elo
Milestone P2.1 observed that Hybrid H2 (50% Classical + 50% NNUE) scored 99.0% against pure H1. 
Milestone P2.2 executed the missing scientific control: **Hybrid H2 vs Classical R1.0** (50 games, $5\text{s}+0.05\text{s}$, opening pair symmetry).
- **Match Result:** H2 scored **4.0 / 50 (+0 =8 -42) | 8.0% | Elo: -424.3** vs Classical R1!
- Pentanomial distribution: `[17, 8, 0, 0, 0]` (17 double-losses, 8 loss-draws, 0 wins).
- Paired 95% Confidence Interval: $[3.3\%, 12.7\%]$, $p < 0.0001$.

**Scientific Conclusion:** Hybrid H2 does not enhance Classical R1. Injecting H1's noisy, compressed evaluation into R1 severely contaminates classical alpha-beta pruning, causing an catastrophic 424 Elo loss. H2's 99% score against H1 in P2.1 was an artifact of H1 being even weaker (-727 Elo).

## 5. Engineering Remedies & Experimental Validations

### 5.1 Training Objective Reform: Lambda-Loss Pilot (Phase 9)
To prove the causal attribution of Root Causes 1, 2, and 3, a controlled 5-epoch pilot retraining experiment was conducted with a blended Lambda-Loss:
$$\mathcal{L} = (1 - \lambda) \cdot \mathcal{L}_{\text{BCE}}(\hat{y}, z) + \lambda \cdot \mathcal{L}_{\text{MSE}}(\hat{y}, y_{\text{teacher}}), \quad \lambda = 0.8$$
Where $y_{\text{teacher}} = \tanh(\text{Score}_{\text{classical}} / 400.0)$.

**Experimental Results:**
```

========================================================================================================================

-----------------------------+--------------------------+-------------------------------+-------------------------------

Knight Margin                | +174 cp                  | +105 cp                       | Realistic scale
Queen Margin                 | +151 cp                  | +140 cp                       | Restores Q > N (RESOLVED)
Queen / Knight Ratio         | 0.87 (INVERTED)          | 1.33 (MONOTONIC)              | Monotonic hierarchy restored
Centipawn Calibration Scale  | 4x-10x compressed        | Grounded to classical scale   | Search bounds aligned
========================================================================================================================
```
This empirically confirms that teacher score grounding eliminates the $+52\text{ cp}$ bias and restores correct relative piece values.

### 5.2 Scalable Self-Play Data Pipeline (Phase 10)
A clean-room self-play generation tool (`generate_self_play_dataset.py`) was engineered:
- Uses `janus_classical_r1.exe` as self-play teacher.
- Records FEN, played move, game outcome, and depth-searched centipawn root scores.
- Automatically partitions datasets by unique game ID into Train ($80\%$) and Validation ($20\%$).
- Pilot generation of 30 games produced 802 unique positions with zero leakage, proving pipeline readiness for Milestone P2.3.

### 5.3 Feature Representation Expansion Analysis (Phase 11)
Four candidate feature representations were benchmarked across memory footprint, expressiveness, and sample requirements:
- **F0 (DP-PS-768):** $106\text{k}$ parameters ($200\text{ KB}$). Zero king conditioning; cannot encode king safety.
- **F1 (Standard HalfKP-40960):** $5.25\text{M}$ parameters ($10\text{ MB}$). Full king-piece conditioning; standard in elite NNUE engines. Requires $\ge 500,000$ positions.
- **F2 (King-Bucketed KP-24576):** $3.15\text{M}$ parameters ($6\text{ MB}$). Reduces parameters but introduces boundary discontinuities.
- **F3 (Compact King-Zone):** $532\text{k}$ parameters ($1\text{ MB}$). Intermediate representation.

**Formal Decision:** **Select F1 (Standard HalfKP-40960)** for Milestone P2.3, paired with a $500,000$-position self-play training campaign.
