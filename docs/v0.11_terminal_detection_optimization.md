## 1. Executive Summary

Milestone **v0.11** implements a narrowly scoped optimization in Project Janus's alpha-beta search pipeline (`src/janus/search.py`) targeting the single largest compute bottleneck identified in the v0.10 profiling milestone: **redundant terminal position detection and legal move generation during stalemate and checkmate checks**.

### Key Results
- **Strict Tree Invariance:** Total node counts, per-position node counts, returned best moves, root evaluations, and principal variations are **100% identical** across all benchmark positions at both Depth 3 (13,999 nodes) and Depth 4 (71,195 nodes).
- **Depth 4 Search Speedup:** Median independent-process runtime dropped from **5.141s to 3.969s (-1.172s, +22.8% speedup)**, perfectly confirming the projected 15–25% speedup hypothesis.
- **Depth 3 Search Speedup:** Median runtime dropped from **0.719s to 0.656s (+8.8% speedup)**.
- **Profiling Elimination:**
  - `board.is_stalemate()` was called **71,172 times** in v0.10 (consuming 5.132s cumulative time). In v0.11, it is called **0 times**.
  - `board.is_check()` calls plummeted from **199,848 to 57,547** (saving 1.92s).
  - Total `cProfile` benchmark execution time dropped from **33.95s to 21.15s (-37.7%)**, with 1.47 million function calls eliminated.
- **Regression Suite:** Expanded from 40 to **49 passing tests** with 9 new focused regression tests in `tests/test_terminal_detection.py`.

## 3. Terminal-Detection Audit & Correctness Argument

### 3.1 The Redundancy Diagnosis
In the v0.10 implementation, every visited node in `_negamax` and `_quiescence` invoked `_terminal_score(board, ply)`:
```python
def _terminal_score(self, board: chess.Board, ply: int) -> Optional[int]:
    if board.is_checkmate():
        return -MATE_SCORE + ply
    if (
        board.is_stalemate()
        or board.is_insufficient_material()
        or board.is_fivefold_repetition()
        or board.is_seventyfive_moves()
    ):
        return 0
    return None
```
In `python-chess`:
1. `board.is_checkmate()` checks `self.is_check() and not any(self.generate_legal_moves())`.
2. `board.is_stalemate()` checks `not self.is_check() and not any(self.generate_legal_moves())`.

For every non-check position (which represents >90% of all chess tree states):
- `is_checkmate()` checks `is_check()` -> `False`.
- `is_stalemate()` checks `not is_check()` -> `True` -> generates legal moves to verify non-emptiness.
- Then, in `_negamax`, line 256 calls `_ordered_moves(board, tt_move, ply)`, which generates all legal moves **a second time**.
- In `_quiescence`, `is_checkmate()` and `is_stalemate()` were executed at every non-check node even though quiescent nodes only search captures.

### 3.2 Correctness Proofs

#### Invariant A: Internal Negamax Nodes (`depth > 0`)
- **Theorem:** If `moves = self._ordered_moves(board, tt_move, ply)` has already generated `list(board.legal_moves)`:
  - If `moves` is non-empty: the position cannot be checkmate or stalemate (`len(moves) > 0`).
  - If `moves` is empty: the position is checkmate if and only if `board.is_check()` is `True`. Otherwise, it is stalemate.
- **Proof:** FIDE Rule 5.1/5.2. In chess, a player with no legal moves is checkmated if in check, and stalemated if not in check. Reusing `not moves` is mathematically identical to `is_checkmate()` and `is_stalemate()` while eliminating the duplicate legal move generation pass entirely.
- **Rule-Mandated Draws:** Fast draw rules (`is_insufficient_material()`, `is_fivefold_repetition()`, `is_seventyfive_moves()`) do not generate legal moves and are evaluated at the top of `_negamax`.

#### Invariant B: Negamax Leaf Nodes (`depth <= 0`)
- At search horizon `depth <= 0`, if the preceding move delivered checkmate or stalemate, the game has terminated and must not enter quiescence search.
- Evaluating `if not any(board.generate_legal_moves()): return (-MATE_SCORE + ply if board.is_check() else 0), []` immediately resolves terminal leaves without redundant checking, preserving exact mate and draw scores before entering quiescence.

#### Invariant C: Quiescence Search (`_quiescence`)
- **In-Check Nodes:** Quiescence generates all legal evasions via `moves = self._ordered_moves(board, None, ply)`. If `not moves`, it returns `-MATE_SCORE + ply`. Calling `is_checkmate()` at the entrance is 100% redundant, and stalemate while in check is impossible.
- **Non-Check Nodes:** Checkmate is impossible when `not in_check`. Stalemate is only possible if no legal moves exist. Checking `if not any(board.generate_legal_moves()): return 0` stops at the first generated legal move.

## 4. Files and Functions Changed

### `src/janus/search.py`
1. **`_terminal_score`:**
   Streamlined to avoid duplicate `is_check()` calls and move generator passes. Retained as a public/internal helper for backward compatibility:
   ```python
   def _terminal_score(self, board: chess.Board, ply: int = 0) -> Optional[int]:
       if (
           board.is_insufficient_material()
           or board.is_fivefold_repetition()
           or board.is_seventyfive_moves()
       ):
           return 0
       if board.is_check():
           if not any(board.generate_legal_moves()):
               return -MATE_SCORE + ply
       elif not any(board.generate_legal_moves()):
           return 0
       return None
   ```
2. **`_negamax`:**
   - Evaluates fast draw rules at entry.
   - For `depth <= 0`, checks terminal leaves before qsearch entry.
   - For `depth > 0`, checks `if not moves:` immediately following `_ordered_moves`:
     ```python
     moves = self._ordered_moves(board, tt_move, ply)
     if not moves:
         if board.is_check():
             return -MATE_SCORE + ply, []
         return 0, []
     ```
3. **`_quiescence`:**
   - Replaced redundant `_terminal_score` call with fast draw rules.
   - In-check nodes detect checkmate directly from evasion moves list (`if in_check and not moves: return -MATE_SCORE + ply`).
   - Non-check nodes check stalemate only when no legal moves exist.
4. **`search` Root Node:**
   - Reuses already-generated `legal_moves`: `score = -MATE_SCORE if board.is_check() else 0`.

## 8. Unresolved Risks

1. **Draw Rules Coverage:** Fifty-move and repetition checks are evaluated only at `is_seventyfive_moves()` and `is_fivefold_repetition()`. Standard competition three-fold repetition and fifty-move claim rules remain future work.
2. **Quiescence Horizon:** In positions with no legal moves, checking `not any(generate_legal_moves())` inside `_quiescence` stops at the first legal move, but non-check stalemates in quiescence are exceedingly rare.

---

## 9. Recommendations for Milestone v0.12

With terminal detection optimized and move generation redundancy eliminated:
1. **Zobrist Hashing for Transposition Table:** Replace `board.fen(en_passant="legal")` dictionary keys with 64-bit integer Polyglot Zobrist hashes. Profiling shows FEN formatting takes ~1.1s for only 3,820 calls; Zobrist hashing will eliminate all string allocations.
2. **Move Generation Optimization in Quiescence:** Use pseudo-legal captures and filter with `board.is_legal()` to avoid full legal move generators in qsearch.
