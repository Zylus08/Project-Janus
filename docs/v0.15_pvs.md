## 3. PVS Implementation Details (Step 1)

### 3.1 Mathematical Negamax Formulation
In negamax alpha-beta search, the search window $[ \alpha, \beta ]$ represents the range within which the exact minimax score must be resolved.
When move ordering places the principal variation (PV) move first:
1. **First Move ($i = 0$):**
   Search with the full window:
   $$\text{child\_score} = -\text{negamax}(\text{board}, \text{depth} - 1, -\beta, -\alpha, \text{ply} + 1)$$
2. **Subsequent Moves ($i > 0$):**
   Test the hypothesis that the move cannot exceed $\alpha$ (cannot improve the position) by executing a null-window (scout) search with parent window $[\alpha, \alpha + 1]$. In negated child coordinates, this transforms to $[ -\alpha - 1, -\alpha ]$:
   $$\text{score} = -\text{negamax}(\text{board}, \text{depth} - 1, -\alpha - 1, -\alpha, \text{ply} + 1)$$
3. **Scout Refutation (Fail Low):**
   If $\text{score} \le \alpha$, the move is proven unable to beat the PV move. No further work is required.
4. **Scout Fail High & Re-search Condition:**
   If $\text{score} > \alpha$:
   - If $\text{score} < \beta$: The move refuted the scout null-window and may represent a new superior line. It is re-searched with the full window:
     $$\text{score} = -\text{negamax}(\text{board}, \text{depth} - 1, -\beta, -\alpha, \text{ply} + 1)$$
   - If $\text{score} \ge \beta$: The move immediately causes a beta cutoff, bypassing full re-search.

### 3.2 Shallow Depth Gating
Empirical testing revealed that running scout searches at `depth == 1` causes premature fail-highs against leaf quiescence searches, triggering redundant re-searches. By conservatively gating scout searches to `depth >= 2`, leaf-level horizon nodes evaluate directly with full alpha-beta windows.

### 3.3 Core Code in `src/janus/search.py`
```python
        moves_searched = 0

        for move in moves:
            board.push(move)
            try:
                if self.enable_pvs and moves_searched > 0 and depth >= 2:
                    # Null-window scout search [-alpha - 1, -alpha]
                    self.scout_searches += 1
                    child_score, child_pv = self._negamax(
                        board, depth - 1, -alpha - 1, -alpha, ply + 1
                    )
                    score = -child_score

                    if score > alpha:
                        self.scout_fail_highs += 1
                        if score < beta:
                            self.researches += 1
                            child_score, child_pv = self._negamax(
                                board, depth - 1, -beta, -alpha, ply + 1
                            )
                            score = -child_score
                else:
                    # Full-window search (first move, shallow depth, or PVS disabled)
                    child_score, child_pv = self._negamax(
                        board, depth - 1, -beta, -alpha, ply + 1
                    )
                    score = -child_score
            finally:
                board.pop()

            moves_searched += 1
```

### 3.4 Preservation of Search Invariants
- **Beta Cutoffs:** Normal beta-cutoff triggers (`alpha >= beta`) remain intact. Killers and quiet history bonuses are updated upon cutoff.
- **Transposition Table Bound Soundness:**
  - Nodes failing low in scout searches store `upper` bound entries.
  - Nodes causing cutoffs store `lower` bound entries.
  - Re-searched nodes producing exact scores store `exact` entries.
- **Mate Distance Encoding:** Unaffected; normalization via `_score_to_tt` and `_score_from_tt` operates identically.
- **Toggle Mechanism:** `enable_pvs: bool = True` added to `JanusSearch.__init__` and exposed via CLI flag `--no-pvs` in `scripts/benchmark.py`.

## 4. Telemetry Instrumentation (Step 2)

Four dedicated counters were integrated into `JanusSearch` and `SearchResult`:
1. `scout_searches`: Total null-window searches executed on moves $i \ge 1$ at `depth >= 2`.
2. `scout_fail_highs`: Scout searches returning `score > alpha`.
3. `researches`: Full-window re-searches launched when `score > alpha and score < beta`.
4. `beta_cutoffs`: Beta cutoffs triggering in `_negamax`.
5. `nodes`: Total nodes visited across `_negamax` and `_quiescence`.

Counters are reset at the beginning of each `search()` call and exported in `SearchResult` and `scripts/benchmark.py` JSON reports.

## 6. Pre-Commit Discrepancy Audits

### 6.1 Benchmark Methodology Audit (v0.14 vs. v0.15 Baseline Runtimes)
During the audit, the v0.14 Depth-4 median (3.711s) was cross-referenced against the initial v0.15 PVS-disabled baseline median (7.343s–7.640s). Investigation revealed:
1. **Search Tree Invariance:** Both v0.14 and v0.15 PVS-disabled explore **exactly 67,029 nodes** across the 6 benchmark positions. The game trees, evaluations, and move ordering are 100% identical.
2. **Hardware Power State Shift:** In milestone v0.14, the benchmark suite was executed while the host laptop was connected to AC mains with Intel turbo boost active (~4.5 GHz), yielding ~18,062 nodes/second. In milestone v0.15, sustained Depth 5 benchmark repetitions heated the CPU and the machine operated on DC battery power (<20% battery charge in Windows Battery Saver Mode), causing CPU power throttling to ~2.3 GHz and dropping throughput to ~8,773 nodes/second.
3. **Paired Run Consistency:** When benchmarked under identical contemporaneous conditions within the same session, PVS consistently saves 18,721 nodes (-27.93%) at Depth 4 and reduces runtime by ~50%.

### 6.2 Beta-Cutoff Telemetry Audit
In the initial report draft, the baseline column for Beta Cutoffs displayed `0`. Investigation confirmed:
1. **Identical Semantic Accounting:** The counter `self.beta_cutoffs += 1` increments inside `_negamax` whenever `alpha >= beta` triggers, immediately before `break`. It executes identically whether PVS is enabled or disabled.
2. **Transcription Correction:** The raw benchmark JSON records **305 cutoffs at Depth 3**, **2,727 cutoffs at Depth 4**, and **6,333 cutoffs at Depth 5** for the PVS-disabled baseline. The initial report erroneously transcribed `0` in the baseline column alongside the scout search metrics.
3. **No Double-Counting:** Beta cutoffs occur at most once per node, and scout re-searches are tracked separately via `self.researches`.

1. **Milestone v0.16 Proposed Scope: Aspiration Windows & Late Move Reductions (LMR)**:
