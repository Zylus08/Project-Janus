## 1. Executive Summary

Milestone **v0.18** introduces conservative **Late Move Reductions (LMR)** into the interior-node search of Project Janus. LMR prunes search effort by searching late, quiet non-tactical candidate moves with a reduced search depth ($\text{depth} - 1 - R$). When a reduced search demonstrates that a move has the potential to exceed $\alpha$, a verification re-search at full depth is executed.

## 2. LMR Policy and Eligibility Conditions (Phase 2)

LMR is enabled via `enable_lmr: bool = True` (configurable) and can be disabled on the CLI via `--no-lmr`.

### 2.1 Conservative Reduction Conditions
An interior-node move is eligible for reduction if and only if **all** of the following conditions are met:
1. `self.enable_lmr` is True.
2. `moves_searched >= 3`: The first 3 moves (PV move, killer moves, and primary tactical candidates) are searched at full depth. Only move index 3 onwards is eligible.
3. `depth >= 3`: Shallow depths are protected. With a 1-ply reduction ($R = 1$), the reduced depth $\text{depth} - 1 - R \ge 1$, guaranteeing that leaf quiescence search is never called prematurely.
4. `ply > 0`: Root moves (`ply == 0`) are strictly excluded from reduction.
5. `not board.is_check()`: Nodes in check are never reduced; all evasions are evaluated at full depth.
6. `not board.is_capture(move)`: Tactical captures are strictly excluded.
7. `move.promotion is None`: Pawn promotions are strictly excluded.
8. `not board.gives_check(move)`: Moves that deliver check are strictly excluded.
9. `move != killer_1 and move != killer_2`: Quiet killer moves stored in the heuristic slots for the current ply are protected from reduction.

### 2.2 Reduction Formula
For eligible moves, a conservative 1-ply reduction is applied:
$$R = 1, \quad \text{reduced\_depth} = \max(1, \text{depth} - 1 - R)$$

## 3. Search Flow, Verification, and Cutoff Semantics

### 3.1 PVS Scout Search Integration
When LMR is applied inside Principal Variation Search (PVS):
1. **Reduced Scout Search:**
   The move is searched with a null window at reduced depth:
   $$\text{score} = -\text{negamax}(\text{board}, \text{reduced\_depth}, -\alpha - 1, -\alpha, \text{ply} + 1)$$
2. **Refutation (Fail-Low, $\text{score} \le \alpha$):**
   The move failed to beat $\alpha$ even with a shallower horizon. The move is refuted; no re-search is required (`lmr_fail_lows += 1`).
3. **Verification Re-Search (Fail-High, $\text{score} > \alpha$):**
   The move scored above $\alpha$ (`lmr_fail_highs += 1`, `lmr_researches += 1`). It is immediately re-searched at full depth:
   - First, a full-depth scout search at $\text{depth} - 1$ with $[-\alpha - 1, -\alpha]$.
   - If the full-depth scout search also fails high and $\text{score} < \beta$, a full-window re-search $[-\beta, -\alpha]$ at $\text{depth} - 1$ is executed.
4. **Beta Cutoff Verification Policy:**
   A reduced search result that scores $\ge \beta$ is **never** accepted as an immediate beta cutoff. Because $\text{score} \ge \beta > \alpha$, it triggers the full-depth verification search. A beta cutoff is accepted only after the full-depth search confirms $\text{score} \ge \beta$.
5. **Killer and History Heuristic Updates:**
   Quiet move history and killer heuristics are updated exclusively from the verified search results.

## 4. Telemetry Architecture (Phase 3)

Seven dedicated LMR counters were added to `JanusSearch` and `SearchResult`:

| Counter | Semantics |
|---|---|
| `lmr_considered` | Number of moves meeting all LMR eligibility criteria. |
| `lmr_reduced_searches` | Number of actual reduced searches executed. |
| `lmr_reduced_plies` | Total plies of search depth saved across all reduced searches. |
| `lmr_researches` | Number of full-depth verification re-searches triggered by reduced fail-highs. |
| `lmr_fail_lows` | Number of reduced searches returning $\text{score} \le \alpha$ (successful refutations). |
| `lmr_fail_highs` | Number of reduced searches returning $\text{score} > \alpha$ (triggered verification). |
| `lmr_cutoffs` | Number of beta cutoffs produced by an LMR-eligible move after full verification. |

All counters reset to zero at the start of each `search()` call and remain completely orthogonal to PVS and Aspiration telemetry.
