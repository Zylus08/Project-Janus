## 1. Executive Summary

Milestone **v0.19** introduces conservative, independently configurable **Null Move Pruning (NMP)** to the interior-node alpha-beta search of Project Janus.

Null Move Pruning tests the null-move hypothesis: if the side to move can pass their turn (a null move) and still produce a search score that meets or exceeds $\beta$ at a reduced depth ($R = 2$), the position is so commanding that searching all legal moves is unnecessary. To prevent false cutoffs in zugzwang-prone and tactical endgames, NMP incorporates a strict material eligibility predicate and an adaptive verification search policy.

## 2. NMP Architecture & Eligibility Conditions

NMP is implemented in `_negamax` in `src/janus/search.py` before legal move generation. It executes only when all of the following conditions hold:

1. **Global Configuration:** `self.enable_nmp: bool = True` (independently switchable, or toggled off via CLI flag `--no-nmp`).
2. **Execution Context:** `allow_nmp: bool = True`. Explicitly set to `False` in null-move child searches and verification searches to forbid nested or double null moves.
3. **Interior Node Only:** `ply > 0`. Null moves are strictly forbidden at the root, ensuring the root search always evaluates legal moves and maintains a legal principal variation.
4. **Depth Boundary:** `depth >= 3`. Ensures the reduced search depth $\text{depth} - 1 - R \ge 0$ ($R = 2$).
5. **Node In Check:** `not board.is_check()`. Passing the turn while in check is illegal in chess and invalid in alpha-beta search.
6. **Suitable Search Window:** `abs(beta) < MATE_THRESHOLD`. Disallowed when searching for checkmate evasion or mate delivery.
7. **Rule-Mandated Draw Guard:** `board.halfmove_clock < 140`. Disallowed near the 75-move draw threshold to avoid false draw horizons.
8. **No Consecutive Null Moves:** `not (len(board.move_stack) > 0 and board.peek() == chess.Move.null())`.
9. **Material Eligibility Predicate (`_has_nmp_material`):**
   - Strictly excludes pawn-only endgames (K+P vs ...) where zugzwang risk is acute.
   - Strictly excludes single minor-piece endgames (K+N vs ... or K+B vs ...).
   - Requires the side to move to possess:
     - At least 1 Queen, OR
     - At least 1 Rook, OR
     - At least 2 minor pieces (Knights/Bishops).

## 3. Reduction, Verification & Cutoff Semantics

### Search Execution
- **Reduction:** Fixed conservative reduction of $R = 2$ plies.
- **Child Search Depth:** `reduced_depth = max(0, depth - 1 - 2)`.
- **Search Window:** Null-window `[-beta, -beta + 1]` in child perspective.
- **Exception Safety:** Board push and pop are wrapped in `try ... finally: board.pop()`, guaranteeing full board restoration even if search is interrupted.

### Adaptive Verification Search Policy
A null-move fail-high ($\text{score} \ge \beta$) is subject to verification:
- **Condition:** Verification is triggered if `depth >= self.nmp_verify_min_depth` (default: 5) OR if either side has low piece count ($\le 2$ non-pawn pieces).
- **Execution:** A verification search is executed at `v_depth = max(1, depth - self.nmp_reduction)` with `allow_nmp=False` and window `[beta - 1, beta]`.
- **Verification Failure:** If `v_score < beta`, the candidate cutoff is rejected as a potential zugzwang false positive or tactical illusion. `nmp_verification_failures` is incremented, and normal legal move search resumes.
- **Verification Success:** If `v_score >= beta`, the cutoff is confirmed. `nmp_cutoffs` is incremented.

### Cutoff Contract and Transposition Table Bounds
When an NMP cutoff is accepted:
1. `score` is clamped to $\beta$.
2. Transposition table entry is stored with `flag = "lower"`, `score = self._score_to_tt(beta, ply)`, and `best_move = tt_move` (preserving previously known best move; never storing a null move).
3. The function returns `beta, []`. An empty PV is returned so that null moves never pollute the principal variation.
4. Killer-move and history-heuristic tables are **not** updated, preventing null-move pollution of move ordering.

| **1. LMR OFF, NMP OFF** (Pure PVS/Aspiration) | 13,439 | 48,229 | 189,535 | 0.00% (Baseline) |
| **2. LMR ON, NMP OFF** (v0.18 Baseline) | 13,439 | 45,239 | 77,878 | -58.91% |
| **3. LMR OFF, NMP ON** (NMP Alone) | 13,439 | 29,521 | 108,860 | -42.56% |
| **4. LMR ON, NMP ON** (v0.19 Candidate) | 13,439 | **26,409** | **53,707** | **-71.66%** |

### Ablation Insights
- **NMP Alone vs LMR Alone:** At Depth 4, NMP alone achieves a larger node reduction (-38.8%) than LMR alone (-6.2%). At Depth 5, both techniques provide massive pruning independently.
- **Compositional Synergy:** LMR and NMP compose gracefully without interference or thrashing. Together, they reduce Depth-5 search tree nodes from 189,535 down to **53,707** (**-71.66%**), delivering an overall **3.7x search tree compression** over pure PVS.
