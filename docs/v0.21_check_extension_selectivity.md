# Project Janus — Milestone v0.21
## Selective Check Extensions: Single-Reply Policy & Controlled Evaluation

### 1. Executive Summary

Milestone v0.21 evaluates whether a more selective check-extension policy offers a superior trade-off between search cost and tactical reliability compared to the unbounded/all-checks bounded extension policy introduced in v0.20.

Three independent search policies were implemented, verified, and compared across reproducible suites:
1. **`disabled` (control)**: Zero check extensions applied, strictly reproducing v0.20 extensions-off behavior.
2. **`bounded_all_checks`**: Extends every eligible in-check node by 1 ply, bounded by `max_check_extensions = 2` along any search path (preserving v0.20 extensions-on behavior).
3. **`single_reply`**: Evaluates legal evasions at eligible in-check nodes. Grants a 1-ply extension if and only if the side to move has **exactly one legal evasion**, subject to the same `max_check_extensions = 2` budget. Does not extend nodes with multiple evasions, nor terminal checkmate positions.

#### Key Findings
- **Search Efficiency**: On the standard 6-position benchmark suite, `single_reply` substantially curtails search explosion compared to `bounded_all_checks`:
  - Depth 3: `disabled` = 13,439 nodes; `single_reply` = 13,762 nodes (+2.40%); `bounded_all_checks` = 14,791 nodes (+10.06%).
  - Depth 4: `disabled` = 26,409 nodes; `single_reply` = 28,142 nodes (+6.56%); `bounded_all_checks` = 32,867 nodes (+24.45%). Single-reply achieves a **14.38% node reduction** versus bounded all-checks.
  - Depth 5: `disabled` = 53,707 nodes; `single_reply` = 57,905 nodes (+7.82%); `bounded_all_checks` = 73,553 nodes (+36.95%). Single-reply achieves a **21.27% node reduction** versus bounded all-checks (saving 15,648 nodes).
- **Tactical Fidelity**: On the 16-position tactical and endgame reliability suite, `single_reply` preserved 100% of forced mates (2/2 at depth 4) and 100% PV legality (96/96 evaluations valid). In positions with multiple evasions (e.g. `tactical_fork_knight`), `single_reply` avoids spurious tree expansion (2,194 nodes vs 7,502 nodes for all-checks, a 70.8% reduction), while correctly extending forced single evasions (e.g. `forced_single_evasion` Kh1-h2).
- **Decision Gate Recommendation**: While `single_reply` demonstrates clear superiority over `bounded_all_checks` in selectivity and search economy, check extensions overall still add a +7.82% node overhead over `disabled` without yet demonstrating statistically significant match Elo gains. Therefore, the v0.20 default (`check_extension_policy = "disabled"`, `enable_check_extensions = False`) is retained as the production default, with `single_reply` designated as the recommended tactical extension policy for future strength evaluation.
- **Verdict**: **PASS**.

### 2. Architecture & Policy Semantics

#### 2.1 Extension Policies
Extension policies are configured via `JanusSearch(check_extension_policy=...)` or `--check-extension-policy` CLI argument:
- **`disabled`**: Check extension logic is bypassed. `check_extensions_applied = 0`.
- **`bounded_all_checks`**: If `board.is_check()` and `depth > 0`, the node is eligible. If `current_ext < max_check_extensions`, `extension = 1`, incrementing `check_extensions_applied` and `check_extension_plies`. If budget is exhausted, `check_extensions_suppressed += 1`.
- **`single_reply`**: If `board.is_check()` and `depth > 0`, the node is eligible. Legal evasions are probed efficiently using generator iteration (`board.generate_legal_moves()`):
  1. If `first_evasion is None`: Terminal checkmate (0 moves); extension = 0.
  2. If `second_evasion is not None`: Multiple legal replies ($\ge 2$); extension = 0, `check_extensions_multiple_replies += 1`.
  3. If exactly 1 evasion: Single reply! If `current_ext < max_check_extensions`, extension = 1; else `check_extensions_suppressed += 1`.

#### 2.2 Telemetry & Cost Accounting
The search telemetry exposes exact counters with clean reset semantics at the start of each search:
- `check_extensions_eligible`: Number of in-check nodes visited with `depth > 0`.
- `check_extensions_applied`: Total extensions granted (+1 ply).
- `check_extension_plies`: Cumulative plies added to search branches.
- `check_extensions_suppressed`: Eligible nodes denied extension due to path budget (`max_check_extensions = 2`).
- `check_extensions_multiple_replies`: In-check nodes rejected by `single_reply` due to having $\ge 2$ legal evasions.
- `check_extensions_terminal_mates`: Checkmate positions encountered at extended plies.

#### 2.3 Search and Transposition Table Invariants
- **Effective Depth Accounting**: `effective_depth = depth + extension`. Transposition table probes require `entry.depth >= effective_depth`, and store `depth = effective_depth`. Child searches receive `effective_depth - 1`.
- **NMP Invariant**: Null move pruning is never attempted when in check (`not in_check`), regardless of extension state.
- **LMR Invariant**: Evasions and checks are strictly excluded from Late Move Reductions (`not in_check` and `not gives_check`).
- **PVS and Aspiration Coherence**: PV scout searches and aspiration retries respect effective depth bounds and restore alpha-beta windows cleanly upon fail-low/high.

### 5. Tactical & Endgame Evaluation

The 16-position tactical audit suite (`analysis/v0.21/check_extension_selectivity_audit.json`) was evaluated at Depths 3 and 4 across all three policies.

#### 5.1 Tactical Suite Summary
- **Total Evaluations**: 96 search evaluations (16 positions $\times$ 3 policies $\times$ 2 depths).
- **PV Legality Pass Rate**: **100.0%** (96/96 valid).
- **Forced Mates Found at Depth 4**: 2/2 in all configurations (`mate_in_one_scholar`, `mate_in_two_smothered`).
- **Board State Restoration**: 100% exact FEN match.

#### 5.2 Tactical Divergence Analysis
Only two divergences were detected across the entire suite, and both occurred strictly between `bounded_all_checks` and `disabled`:
1. `discovered_check_defense` (Depth 3):
   - `disabled`: `c4f7`, score +84 (9,400 nodes).
   - `single_reply`: `c4f7`, score +84 (9,400 nodes, 8 multiple replies rejected).
   - `bounded_all_checks`: `d1d5`, score +209 (12,335 nodes, 30 extensions applied).
   - *Investigation*: At depth 3, `bounded_all_checks` extended multiple checking moves which pushed `d1d5` over the horizon. At depth 4, all three policies converged onto the identical best move (`d1d5`) and score (+209), with `single_reply` requiring 17,742 nodes versus 19,116 for `bounded_all_checks`.
2. `seventyfive_move_near_draw` (Depth 3):
   - `disabled`: `e1f1`, score -500 (95 nodes).
   - `single_reply`: `e1f1`, score -500 (95 nodes, 5 multiple replies rejected).
   - `bounded_all_checks`: `e1f1`, score 0 (364 nodes, 10 extensions applied).
   - *Investigation*: `bounded_all_checks` extended checks deep enough to hit the 150-halfmove draw boundary within the search horizon. At depth 4, all three policies converged to `e1f1` with score 0.

#### 5.3 Selectivity Case Studies
- `forced_single_evasion` (`8/8/8/8/8/7P/6P1/4r2K w - - 0 1`):
  White's only legal evasion is `h1h2`.

### 7. Decision Gate & Recommended Strategy

#### 7.1 Decision Rules Review
1. *Did single-reply reduce search cost while preserving tactical outcomes?* **Yes.** `single_reply` reduced depth-5 search cost by **21.27%** relative to `bounded_all_checks` while maintaining 100% tactical mate detection and PV legality.
2. *Did bounded all-checks find materially better tactical resources to justify its cost?* **No.** In all 16 tactical tests and 6 benchmark positions, `bounded_all_checks` produced no superior tactical outcomes over `single_reply`, while wasting up to 196% more nodes on check nodes with multiple evasions.
3. *Should single-reply replace disabled as the default engine configuration?* **Not yet.** Check extensions still introduce a +7.82% node overhead relative to `disabled` (+4,198 nodes at depth 5). Until an adequately powered match (e.g. 50–100 games) confirms a net Elo improvement, engine defaults should remain conservative.

#### 7.2 Decision Verdict
- **Default Policy**: Retain `check_extension_policy = "disabled"` (`enable_check_extensions = False`).
- **Recommended Selective Policy**: Designate `single_reply` as the primary tactical extension implementation, replacing `bounded_all_checks` as the candidate extension policy for future playing-strength evaluations.
- **Milestone Outcome**: **PASS**.
