### 1. Executive Summary

Milestone v0.22 introduces a dedicated, fully verified Static Exchange Evaluation (SEE) engine for Project Janus. SEE computes the static exchange outcome of capture sequences on a target square using a swap-list minimax algorithm that accounts for:
- Changing board occupancy and x-ray attacker discovery through sliders (queens, rooks, bishops).
- En passant captures with correct offset pawn removal.
- Pawn promotion bonuses and promotion recaptures.
- Absolute pins to the friendly king via bitwise pin rays.
- King recapture legality (prohibiting king moves into check).

Two distinct search applications were integrated into `src/janus/search.py` and evaluated in a 4-way ablation experiment:
1. **SEE-Based Capture Move Ordering (`enable_see_ordering`)**: Good captures ($SEE \ge 0$) receive priority over quiet moves, while losing captures ($SEE < 0$) are demoted below killer and history moves.
2. **Conservative Quiescence Pruning (`enable_see_pruning`)**: In quiescence search, losing captures ($SEE < 0$) that do not deliver check and are not promotions are pruned when not in check.

### 3. SEE Algorithm and Piece-Value Semantics

#### Centipawn Values
SEE uses the engine's canonical piece values from `janus.evaluation.PIECE_VALUES`:
- Pawn: 100 cp
- Knight: 320 cp
- Bishop: 335 cp
- Rook: 500 cp
- Queen: 900 cp
- King: 20,000 cp

Exchange outcomes are expressed directly in centipawns:
- $SEE > 0$: Materially profitable capture sequence for the side to move.
- $SEE = 0$: Materially neutral trade.
- $SEE < 0$: Materially losing capture sequence.

#### Algorithmic Formulation
The exchange sequence operates as a swap list on target square `to_sq`:
1. **Initial Capture**:
   - Captured piece value $V_{victim}$ is credited.
   - For en passant, $V_{victim} = 100$ and the actual captured pawn square (offset by 8 ranks) is cleared from active occupancy.
   - For pawn promotions, the promotion bonus $(V_{promo} - 100)$ is added to the exchange gain.
2. **Occupancy & X-Ray Updating**:
   - An `active_mask` bitboard tracks available pieces on the board.
   - As each piece moves to `to_sq`, its origin square is cleared from `active_mask`.
   - Diagonal and orthogonal slider attacks through vacated squares are dynamically rediscovered using `board.attackers_mask(side, to_sq, occupied=...) & active_mask`.
3. **Least-Valuable Attacker (LVA) Selection**:
   - Available attackers are evaluated in ascending order of piece value: Pawn $\to$ Knight $\to$ Bishop $\to$ Rook $\to$ Queen $\to$ King.
4. **Legality Validation**:
   - **Absolute Pins**: If an attacker is pinned to the king (`attacker_sq & board.pin_mask(side, king_sq)`), it is permitted to recapture only if the target square lies along the pin ray.
   - **King Legality**: The king may only recapture on `to_sq` if the opponent has no remaining attackers on `to_sq` once the previous piece on `to_sq` is removed.
5. **Minimax Swap List Reduction**:
   Given swap gains $[g_0, g_1, \dots, g_{n-1}]$, the minimax outcome is computed backwards:
   $$R_{k} = g_k - \max(0, R_{k+1})$$
   where $R_{n-1} = g_{n-1}$. If the opponent's recapture yields a net loss, they stand pat ($0$), guaranteeing optimal play for both sides.

### 5. Capture Move Ordering Integration

When `enable_see_ordering = True`:
- Existing priority moves (TT best move, PV move) retain highest priority ($2,000,000+$).
- Captures are evaluated using SEE:
  - **Good / Neutral Captures ($SEE \ge 0$)**: Scored with bonus $1,000,000 + SEE \times 100 + \text{MVV-LVA}$.
  - **Losing Captures ($SEE < 0$)**: Demoted below killer moves and history moves ($50,000 + SEE \times 10 + \text{MVV-LVA}$).
- Killer moves (killer 1: $100,000$, killer 2: $90,000$) and history moves ($0 \dots 10,000$) now cleanly separate good captures from bad captures.
- **Node-Local SEE Caching**: Within a search node, all SEE evaluations for generated moves are stored in a dictionary `node_see`. When both ordering and quiescence pruning are active, SEE is computed exactly once per move per node.

---

### 6. Conservative Quiescence Pruning Policy

When `enable_see_pruning = True`:
In quiescence search (`_quiescence`), candidate captures are evaluated before recursive search. A capture is pruned if and only if **all** of the following conditions hold:
1. **Not in check**: The side to move is NOT in check (`not in_check`).
2. **Not a check evasion**: When the king is in check, all legal evasions are generated and searched; pruning is strictly disabled.
3. **Does not deliver check**: `not board.gives_check(move)` (checking captures are tactically exempt).
4. **Not a pawn promotion**: `move.promotion is None` (all promotions are tactically exempt).
5. **Negative SEE**: $SEE(board, move) < 0$.

If any exemption applies or the exchange is non-negative, the move is searched normally.

### 10. Known Limitations & Configuration Defaults

1. **Python Overhead**: Computing SEE in pure Python incurs higher per-call CPU overhead than native C/C++ bitboard engines. At shallow depths (depth $\le 2$), ordering every capture without pruning can increase wall-clock time even when node counts drop.
2. **Quiescence Pruning Scope**: The pruning policy is strictly conservative—it prunes only non-checking, non-promotion captures with $SEE < 0$ outside of check. More aggressive pruning (such as delta pruning or marginal $SEE \le 0$ pruning) was intentionally excluded to maintain absolute tactical soundness.
3. **Production Defaults**:
   - `enable_see_ordering = False` (Preserved default)
   - `enable_see_pruning = False` (Preserved default)
   - `check_extension_policy = "disabled"` (Preserved default)
   Both SEE features are fully functional and independently selectable via CLI flags (`--enable-see-ordering`, `--enable-see-pruning`).
