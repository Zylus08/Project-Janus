### 1. Match Infrastructure Overview

The Project Janus match-testing framework is housed in `scripts/match.py` with opening suites in `benchmarks/openings.json`. It coordinates head-to-head chess matches over the Universal Chess Interface (UCI) protocol via `python-chess` (`chess.engine.SimpleEngine`).

Prior to Milestone v0.24, the harness was exclusively wired for `Janus vs Stockfish` games, lacking UCI option negotiation for Janus configurations, lacking forfeit handling on unexpected exceptions, and writing summaries only at match completion.

---

### 2. Comprehensive Audit of Verification Criteria

#### 2.1 Paired Openings & Color Reversal
- **Implementation**: In `scripts/match.py`, opening pairs are indexed via `pair_index = i // 2`.
  - Game $2k$: Engine 1 plays White, Engine 2 plays Black from opening $k$.
  - Game $2k+1$: Engine 1 plays Black, Engine 2 plays White from the identical opening $k$.
- **Audit Finding**: Verified. Total color balance is guaranteed: exactly $N/2$ games as White and $N/2$ as Black for even $N \ge 2$. Opening conditions are strictly symmetric across paired games.

#### 2.2 Deterministic Opening Sampling & Reproducible Seeds
- **Implementation**: `load_openings(path, count, seed)` uses a dedicated `random.Random(seed)` instance to shuffle opening indices.
- **Audit Finding**: Verified. Running with the same seed reproduces the exact opening sequence across different runs, platforms, and dates without mutating global RNG state. If `count > len(openings)`, the suite cycles deterministically.

#### 2.3 Time Control & Engine Parity
- **Implementation**: Matches use fixed search depth per move (`chess.engine.Limit(depth=depth)`).
- **Audit Finding**:
  - Both engines receive identical fixed-depth limits on every ply.
  - Stockfish configuration options (`Threads`, `Hash`, `Skill Level`, `UCI_Elo`) are logged explicitly in `metadata` and applied via `engine.configure()`.
  - Fixed-depth matches measure tactical and positional strength *at that search depth*; they do not reflect clock-based time-management or speed differences. This distinction is explicitly reported.

#### 2.4 W/D/L & Score Aggregation
- **Implementation**: `summarize(rows)` computes:
  - $\text{Wins} = \sum [(\text{Result} = 1\text{-}0 \land \text{Color} = \text{White}) \lor (\text{Result} = 0\text{-}1 \land \text{Color} = \text{Black})]$
  - $\text{Draws} = \sum [\text{Result} = 1/2\text{-}1/2]$
  - $\text{Losses} = \sum [(\text{Result} = 0\text{-}1 \land \text{Color} = \text{White}) \lor (\text{Result} = 1\text{-}0 \land \text{Color} = \text{Black})]$
  - $\text{Points} = \text{Wins} + 0.5 \times \text{Draws}$
  - $\text{Score \%} = 100 \times \frac{\text{Points}}{\text{Completed Games}}$
- **Audit Finding**: Verified. Scoring logic is mathematically symmetric and accounts for unfinished games (`*`) separately.

#### 2.5 Statistical Uncertainty Protocol
- **Improvement**: Standard error and 95% confidence intervals are now computed directly in `summarize(rows)`.
- **Methodology**: In chess matches, game scores $x_i \in \{0.0, 0.5, 1.0\}$. The sample variance is:
  $$\hat{\sigma}^2 = \frac{1}{N - 1} \sum_{i=1}^N (x_i - \hat{p})^2 = \frac{W(1 - \hat{p})^2 + D(0.5 - \hat{p})^2 + L(0 - \hat{p})^2}{N - 1}$$
  $$\text{SE} = \sqrt{\frac{\hat{\sigma}^2}{N}}$$
  $$\text{CI}_{95\%} = [\max(0\%, 100(\hat{p} - 1.96 \cdot \text{SE})), \; \min(100\%, 100(\hat{p} + 1.96 \cdot \text{SE}))]$$
- **Audit Finding**: Confidence intervals are now reported in JSON, CSV, and console summaries to prevent declaring noisy score fluctuations as strength gains.

#### 2.6 Fault-Tolerant Forfeit Handling & Crash Resilience
- **Prior Defect**: If an engine crashed, emitted an illegal move, or raised an exception during `play_one_game`, an unhandled `RuntimeError` was raised, aborting all remaining games in the match.
- **Resolution**:
  - In `play_one_game`, exceptions and illegal move detections are caught cleanly.
  - The offending engine forfeits the game immediately (`termination = "illegal move by <name>"` or `"crash/error by <name>"`), with the non-offending engine awarded the win ("1-0" or "0-1").
  - The game is appended to rows and the match continues with the next game.

#### 2.7 Partial Result Preservation
- **Prior Defect**: Results were only written to disk upon normal match completion. An interrupted process or unexpected OS termination lost all completed games.
- **Resolution**:
  - `write_reports(json_path, csv_path, rows, metadata, elapsed)` is invoked and flushed after **every single completed game**.
  - PGN games are written and flushed immediately upon game conclusion.
  - Any interrupted run leaves valid, complete PGN, CSV, and JSON files on disk reflecting all finished games.

#### 2.8 Paired Configuration Comparisons (Janus vs Janus)
- **Prior Limitation**: The harness only supported testing against an external binary (`--stockfish`). It could not directly test Janus configurations against each other (e.g. baseline vs candidate).
- **Resolution**:
  - `src/janus/uci.py` now supports standard UCI `setoption` negotiation (`SEE_Ordering`, `SEE_Pruning`, `CheckExtensions`, `TT_Policy`, `Hash`) as well as CLI startup flags (`--see`, `--check-extensions`, `--tt-policy`, `--name`).
  - `scripts/match.py` now features a `--candidate-see` flag that directly configures `Janus-Baseline` (SEE OFF) against `Janus-SEE` (SEE ON) in a paired, symmetric head-to-head match. Custom engines can also be passed via `--engine1-cmd` and `--engine2-cmd`.
