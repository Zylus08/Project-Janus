### 1. Executive Summary

Milestone v0.30 executes an autonomous, profiling-directed optimisation of the quiescence search hot path in Project Janus: **eliminating redundant legal-move generation on root quiescence entry**.

In Milestone v0.29, search profiling established that legal move generation (`chess.Board.generate_legal_moves()`) accounted for **35.4% of total search runtime**. Profiling the quiescence search flow in Milestone v0.30 revealed a critical redundancy at the leaf transition between negamax and quiescence search:
1. In `_negamax`, at `depth <= 0`, the engine checks whether any legal moves exist:
   ```python
   if not any(board.generate_legal_moves()):
       return (-MATE_SCORE + ply if board.is_check() else 0), []
   return self._quiescence(board, alpha, beta, ply), []
   ```
2. When `_quiescence` was entered, line 602 immediately repeated the exact same check on the exact same board state:
   ```python
   if not in_check:
       if not any(board.generate_legal_moves()):
           return 0
   ```
3. Because all terminal states (checkmate and stalemate) were already identified and returned at `depth <= 0` in `_negamax`, every board reaching `_quiescence` from `_negamax` is guaranteed to have at least one legal move. The second `generate_legal_moves()` call was **100% redundant**.

During a 6-position search at depth 5, `_quiescence` was entered from `_negamax` 21,464 times. In all 21,464 instances, `not any(board.generate_legal_moves())` executed fully, never found stalemate, and returned `False`.

By parameterising `_quiescence` with `check_stalemate: bool = True` and passing `check_stalemate=False` only on root entry from `_negamax` (while preserving `check_stalemate=True` by default for recursive quiescence calls), the engine eliminates **21,464 redundant legal-move generation calls** per depth-5 pass without modifying search tree topology, evaluation scores, move decisions, or production configuration defaults.

#### Key Findings & Performance Outcomes

1. **Call Count Reduction:**
   - **Depth 4:** 5,284 redundant `generate_legal_moves()` calls eliminated.
   - **Depth 5:** 14,827 redundant `generate_legal_moves()` calls eliminated.
   - **Combined Profiling Run:** 21,464 calls avoided (-10.6% total `generate_legal_moves()` calls).

2. **Benchmark Speedup (5 Interleaved Repetitions, Depths 4 & 5):**

   - **Tactical Positions:** `mate_in_one` depth 5 improved from 0.846s to 0.539s (**+39.3% median speedup**).
   - **Full Test Suite Runtime:** Dropped from 281.44s to 204.92s (**-76.52s, a 27.2% overall test suite speedup** across 262 tests).

3. **Search Invariance & Correctness:**

### 2. Original Control Flow & Redundancy Analysis

#### Original Control Flow (`src/janus/search.py`)

At the leaf transition in `_negamax`:
```python
# Lines 671-675 in src/janus/search.py (v0.29)
if depth <= 0:
    if not any(board.generate_legal_moves()):
        return (-MATE_SCORE + ply if board.is_check() else 0), []
    return self._quiescence(board, alpha, beta, ply), []
```

Inside `_quiescence`:
```python
# Lines 582-612 in src/janus/search.py (v0.29)
def _quiescence(self, board: chess.Board, alpha: int, beta: int, ply: int) -> int:
    self.nodes += 1
    self._check_stop()

    if board.is_check():
        in_check = True
    else:
        in_check = False

    if not in_check:
        if not any(board.generate_legal_moves()):  # <--- REDUNDANT GENERATION
            return 0
        stand_pat = evaluate_side_to_move(board)
        if stand_pat >= beta:
            return beta
        if stand_pat > alpha:
            alpha = stand_pat
```

#### Correctness and Invariant Proof

- **Precondition at line 675 of `_negamax`:**
  Line 673 checks `if not any(board.generate_legal_moves())`. If the board has no legal moves:
  - If `board.is_check()` is True: returns `-MATE_SCORE + ply` (Checkmate).
  - If `board.is_check()` is False: returns `0` (Stalemate).
  Therefore, execution only reaches line 675 if `any(board.generate_legal_moves())` is **True**.
- **State Invariance:**
  The board object passed to `self._quiescence` at line 675 is unchanged.
- **Root Quiescence Entry:**
  On entry to `_quiescence`, if `not in_check`, evaluating `not any(board.generate_legal_moves())` is strictly redundant: it is guaranteed to evaluate to `False`.
- **Recursive Quiescence Calls:**
  When `_quiescence` searches captures or promotions, moves are pushed onto `board` (`board.push(move)`). A resulting child position might have no legal moves. In that scenario, `check_stalemate=True` is required so stalemate is correctly recognized as 0. Hence, `check_stalemate` must default to `True` for recursive calls.

### 3. Implementation Details

The fix introduces an optional boolean flag `check_stalemate` to `_quiescence` with a default of `True`.
