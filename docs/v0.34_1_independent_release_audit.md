### 1. Executive Summary

This independent release audit provides a forensic evaluation of Project Janus Milestone v0.34. The primary objective was to independently audit the evaluation architecture, weight calibration provenance, ablation performance benchmarks, and confirmatory match data before authorizing further development.

#### Key Findings of the Audit:
1. **Critical Match Integrity Defect Discovered:** Forensic inspection of the raw 100-game dataset (`analysis/v0.34/match/v034_match_500ms.json`) revealed that **Games 56 to 100 were invalidated by an unhandled engine process crash and harness failure**.
   - In Game 56 (Pair 28, Move 99), the candidate engine process died unexpectedly (`exit code: 1`).
   - In Game 58 (Pair 29, Move 6), the reference engine process also died (`exit code: 1`).
   - The match harness in `scripts/match_v034.py` spawned `SimpleEngine` once for the entire match and lacked process supervision or automatic restart logic.
   - For all 44 subsequent games (Games 57–100), the harness called `play()` on dead asyncio event loops. The harness caught the resulting `EngineTerminatedError`, assigned an immediate forfeit against whoever had the move (White on Move 1), and recorded 44 artificial forfeit results.
2. **Colour Imbalance Explained:** The dramatic reported colour disparity (White 39.0%, Black 66.0%) was **100% an artifact of this harness crash cascade**, not an engine evaluation anomaly.
   - In the **55 legitimately played games** (Games 1–55), Candidate v0.34 scored **55.45%** (**30.5 / 55 points**), scoring **51.79% as White** (14.5/28) and **59.26% as Black** (16.0/27) across 27 complete opening pairs (11 Won, 8 Drawn, 8 Lost).
   - In Games 56–100, White forfeited on move 1 in 44 games, artificially handing 44 free points to Black.
3. **Evaluation Implementation Verified Sound:** Independent tests confirmed that the underlying evaluation code in `src/janus/evaluation.py` is robust, deterministic, color-mirror symmetric, and thread-safe. All **314 repository tests** pass cleanly.
4. **Isolated Tapering Overhead Quantified:** Controlled microbenchmarking demonstrated that when positional features are present, the incremental cost of phase-aware tapering over static evaluation is practically negligible: **only +1.3%** in raw throughput ($39,040$ vs $39,566$ evals/sec) and +3.8% in search elapsed time.
5. **Calibration Provenance Reconciled:** The negative calibration result was reproduced with zero discrepancy across all splits. Positional weight tuning on quiet positions without search feedback exhibits severe out-of-sample overfitting ($+4.2\%$ test MSE increase). The decision to reject calibrated weights from production defaults was mathematically and methodologically correct.
6. **Release Decision:** **CONDITIONAL GO** for continued evaluation research (the engine architecture and tapering mechanics are sound and verified), with a strict **NO-GO** on accepting the 100-game match as evidence of playing strength until the harness is repaired and a clean match is executed.

### 5. Colour-Imbalance Investigation

The reported candidate scores were 19.5/50 (39.0%) as White and 33.0/50 (66.0%) as Black.

#### Forensic Analysis of Causes:
1. **Hypothesis A: Coding Bug in Evaluation Inversion:** REJECTED. Unit tests in [`test_v0341_reproducibility.py`](file:///E:/ChessXML/project-janus/tests/test_v0341_reproducibility.py) verified that `evaluate_side_to_move` correctly inverts score for Black (`score if board.turn == chess.WHITE else -score`), and colour-mirror symmetry holds exactly ($S(\text{board.mirror()}) == -S(\text{board})$).
2. **Hypothesis B: Asymmetric UCI Option Handling:** REJECTED. The candidate engine was launched with `--eval-all` at the process level and remained identical for both colours.
3. **Hypothesis C: Crash Cascade Forfeit Mechanism:** **CONFIRMED.** 
   - When an engine process died on Windows, `SimpleEngine`'s event loop was dead.
   - White is the first player to move from any starting position.
   - In `play_one_game`, when the engine whose turn it is raises an exception:
     ```python
     result_string = "0-1" if board.turn == chess.WHITE else "1-0"
     ```
   - In 44 consecutive games, the engine on move was dead, resulting in an automatic `0-1` forfeit win for Black.
   - When isolating the **55 valid games**, White scored **51.79%** and Black scored **59.26%** (a difference of only 7.5%, well within normal binomial variance for $N=55$).

### 10. Limitations and Unresolved Questions

1. **Harness Process Management:** `scripts/match_v034.py` cannot be trusted for long multi-game matches without engine restart and liveness recovery.
2. **Inconclusive Valid Strength Evidence:** While the 55 uncorrupted games yielded an encouraging +38.1 Elo point estimate (30.5 / 55 points, 55.45%), the smaller sample size expands the 95% confidence interval ($[-54.5, +131.7\text{ Elo}]$), rendering the result statistically inconclusive ($p = 0.4918$).
3. **Root Cause of Game 56 Exit Code 1:** Why Janus-v0.34 exited with code 1 at Move 99 in Game 56 on Windows remains unlogged because standard error was not captured by `SimpleEngine.popen_uci`. Potential causes include Windows asyncio pipe buffer exhaustion or memory accumulation across thousands of search worker threads.

### 11. Recommended Next Experiment

The single most useful next step is **not** to implement new chess evaluation features, but to:
1. **Refactor the Match Harness:** Update `scripts/match_v034.py` to restart the engine processes fresh for each game (or opening pair) and add process liveness checks that abort or restart cleanly if an engine dies.
2. **Rerun a Clean 100-Game Validation Match:** Execute a clean 100-game match against reference v0.30 (`05de411`) with process isolation to obtain an uncorrupted, publishable playing-strength measurement for v0.34.
