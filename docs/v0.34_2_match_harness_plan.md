### 1. Root Cause Analysis of the v0.34 Match Crash Cascade

In Milestone v0.34, a 100-game match was run between Candidate v0.34 and Reference v0.30. Milestone v0.34.1's independent release audit discovered that **Games 56 to 100 were invalidated by a cascade of unhandled engine process terminations**.

#### 1.1 The Specific Failure Path
In [`scripts/match_v034.py`](file:///E:/ChessXML/project-janus/scripts/match_v034.py):
```python
with (
    chess.engine.SimpleEngine.popen_uci(base_cmd, cwd=base_dir, env=env_base) as base_eng,
    chess.engine.SimpleEngine.popen_uci(cand_cmd, cwd=cand_dir) as cand_eng,
):
    ...
    for i in range(start_index, games):
        ...
        game_obj, row = play_one_game(...)
```
And inside `play_one_game`:
```python
    for ply in range(max_plies):
        ...
        try:
            res = current_engine.play(board, limit, info=chess.engine.INFO_ALL)
            ...
        except Exception as exc:
            result_string = "0-1" if board.turn == chess.WHITE else "1-0"
            termination_reason = f"engine crash ({curr_name}): {exc}"
            break
```

1. **Monolithic Process Session:** Both engine processes were launched once at the start of the match and shared across all 100 games.
2. **Process Death on Game 56 & 58:**
   - In Game 56 (Pair 28, Move 99), `Janus-v0.34` process terminated with `exit code: 1`.
   - In Game 58 (Pair 29, Move 6), `Janus-v0.30` process terminated with `exit code: 1`.
3. **Dead Event Loop Cascade:**
   When an engine process terminated, `SimpleEngine`'s underlying asyncio transport was closed. The harness caught the resulting `EngineTerminatedError: engine event loop dead` inside `play_one_game`.
4. **Flawed Forfeit Logic:**
   The harness converted infrastructure exceptions directly into chess forfeits (`result_string = "0-1" if board.turn == chess.WHITE else "1-0"`). Because White is to move on Move 1, every game from 57 to 100 crashed on Move 1, awarding an automatic `0-1` win to Black!
5. **No Supervision or Recovery:**
   The harness never checked process health, never restarted dead processes, and never aborted the match.

### 2. Failure Scenarios to Address

| Failure Scenario | Manifestation in v0.34 | Solution in v0.34.2 Supervised Lifecycle |
|---|---|---|
| **Engine Process Termination** | Python process exits with code 1; asyncio transport dies | Fresh process per game; detect exit code, capture stderr, clean up, log attempt failure. |
| **Dead Event Loop Re-use** | Loop called dead engine 44 times in a row | Process isolated per game. Never call dead engine. Process terminated and replaced cleanly. |
| **Infrastructure Failure as Chess Win/Loss** | Crash on Move 1 awarded forfeit win to Black | Explicit distinction: `status = "infrastructure_failure"`, chess result = `None` (`*`). No rating points awarded. |
| **Engine Initialization Hang** | Engine hangs on startup or `isready` | Bounded timeout (5.0s) on initialization; SIGTERM / kill if unresponsive. |
| **Move Timeout / Hang** | Engine hangs inside alpha-beta search | Bounded timeout (`movetime + 5.0s`); graceful stop, then kill if unresponsive. |
| **Uncaptured Stderr** | Exit code 1 occurred with zero diagnostic output | Capture stderr pipe to dedicated log file or in-memory buffer per attempt. |
| **Contaminated Subsequent Games** | State or dead handles leaked across games | Fresh process per attempt guarantees 100% memory and state isolation. |
| **Incomplete Pairs in Analysis** | Forfeited pairs included in paired Elo/t-test | Paired analysis strictly filters for pairs where BOTH games achieved valid chess terminations. |

### 3. Supervised Engine Lifecycle Architecture

#### 3.1 Isolated Per-Game Lifecycle
Rather than sharing a long-lived process across 100 games, each game attempt operates inside a supervised `EngineSession`:
1. **Launch:** `subprocess.Popen` with pipes for `stdin`, `stdout`, `stderr`.
2. **Handshake:** Send `uci`, verify `id name` and `uciok` within 5.0s.
3. **Configure:** Send `setoption name ... value ...` for Hash and Evaluation terms.
4. **Sync:** Send `isready`, verify `readyok` within 5.0s.
5. **Play:** Execute game moves with explicit timeouts per move (`time_limit + 5.0s`).
6. **Teardown:** Send `quit`, wait up to 2.0s, call `terminate()` if not exited, call `kill()` if still running. Close all pipes.
7. **Post-Mortem:** Check `poll()`, record exit code, capture stderr.

#### 3.2 Engine Session Abstraction
A dedicated `SupervisedEngineSession` class handles:
- Starting the subprocess.
- Reading non-blocking stdout lines with deadlines.
- Writing UCI commands.
- Catching crashes, pipe errors, and timeouts.
- Returning structured `EngineResponse(bestmove, score, depth, nodes, time, error)`.

### 4. Failure Policy and Match Integrity Rules

1. **Valid Chess Game Requirement:**
   A game result is valid ONLY IF both engines ran without infrastructure errors and the position reached a standard chess rule termination:
   - Checkmate (`1-0` or `0-1`)
   - Stalemate (`1/2-1/2`)
   - Insufficient material (`1/2-1/2`)
   - Threefold repetition (`1/2-1/2`)
   - Fifty-move rule (`1/2-1/2`)
   - Max plies limit reached (`1/2-1/2`)
2. **Infrastructure Failure Segregation:**
   Any game ending in an engine crash, timeout, invalid move, or protocol failure is tagged `status = "infrastructure_failure"`. The chess score is `None`. It is excluded from all win-rate, Elo, and paired t-test calculations.
3. **Bounded Retries with Strict State Preservation:**
   - Max retries per game slot: **2 retries** (up to 3 attempts total).
   - The opening FEN, opening ID, and colour assignment remain **strictly identical** across retries.
   - Every failed attempt is permanently recorded in `attempt_history` with its attempt ID, error message, exit code, and move count.
4. **Pair Integrity Requirement:**
   An opening pair is eligible for paired analysis ONLY IF both the White game and the Black game completed with valid chess terminations under their intended configurations.
5. **Match Abort Threshold:**
   If more than 3 distinct games fail all retries, or if total infrastructure failures exceed 5 across the match, the match aborts immediately and exits with code 1.
6. **Match Success Criteria:**
   The match exits with code 0 ONLY IF exactly 100 valid chess games across 50 complete opening pairs are achieved.
