## 1. Overview and Problem Statement

Prior to Janus v0.35, the engine's UCI loop parsed only `depth` and `movetime`. When presented with classical clock parameters (`wtime`, `btime`) or Fischer increment parameters (`winc`, `binc`), the engine ignored them and fell back to an unconstrained search to depth 5. This presented three severe architectural deficiencies:
1. **Time Forfeits / Flagging:** Under clock controls, Janus was unaware of remaining time and could not shorten search when low on time.
2. **Increment Underutilization:** In Fischer increment games, Janus could not leverage added increment time per move to search deeper.
3. **Iterative Deepening Overshoot:** The search loop checked deadlines solely inside negamax at node intervals without checking remaining budget at the boundary between iterative-deepening depths.

## 2. Architecture and Component Design

### 2.1 The `TimeManager` Component (`src/janus/time_manager.py`)
A decoupled, stateless, and fully configurable module:
- `TimeManagerConfig`:
  - `safety_reserve_ms: int = 50`: Protocol and OS buffer preventing time forfeits.
  - `default_moves_to_go: int = 30`: Estimated horizon when `movestogo` is omitted.
  - `increment_weight: float = 0.85`: Fraction of increment safely consumed per move.
  - `min_allocation_ms: int = 10`: Minimum useful search slice.
  - `max_allocation_ratio: float = 0.20`: Cap preventing more than 20% of base clock expenditure on a single move.
  - `policy_name: str = "adaptive"`: Policy identifier.
  - `TimeManagerConfig.reference_baseline()`: Factory creating the reference uncalibrated baseline ($W_{\text{inc}} = 0.0, R_{\text{safe}} = 0\text{ ms}, N = 40$).

### 2.2 Mathematical Allocation Pipeline
```python
usable_time = max(0.0, remaining_time - safety_reserve)
base_allocation = usable_time / moves_to_go
target_allocation = base_allocation + (increment_weight * increment)
max_budget = max(min_allocation_ms, min(usable_time, remaining_time * max_ratio + increment))
final_allocation = clamp(target_allocation, min_allocation_ms, max_budget)
```
- **Low-clock emergency handling:** If $T_{\text{rem}} \le R_{\text{safe}}$, allocation is clamped to $\max(1.0, \min(T_{\text{rem}} / 2.0, B_{\text{min}}))$, allowing an immediate fallback move without flagging.
- **Fixed movetime isolation:** `go movetime X` immediately allocates $X / 1000.0$ seconds without clock modification.

### 2.3 Search Loop Boundary Checks (`src/janus/search.py`)
1. **Iterative Deepening Boundary Check:**
   ```python
   for depth in range(1, max_depth + 1):
       if self.stop_event is not None and self.stop_event.is_set():
           break
       if self.deadline is not None and time.monotonic() >= self.deadline:
           break
   ```
2. **Halved Check Interval in Negamax:**
   Deadline is now checked every 128 nodes (`self.nodes & 127 == 0`) rather than 256 nodes, cutting deadline overshoot in half.
3. **Best Move Preservation:** Interrupted search preserves `best_move = pv[0]` from the last fully completed depth. If interrupted at depth 1, `legal_moves[0]` fallback prevents illegal moves.

### 2.4 UCI Interface Extensions (`src/janus/uci.py`)
- Full parsing for `movetime`, `wtime`, `btime`, `winc`, `binc`, `movestogo`, `depth`, and `infinite`.
- Exposes `--time-policy` CLI flag (`adaptive` or `reference`).
- Exposes UCI option `option name Time_Policy type combo default adaptive var adaptive var reference`.
- Dynamic reconfiguration supported via `setoption name Time_Policy value ...`.

### 2.5 Supervised Process Session (`src/janus/engine_session.py`)
`SupervisedEngineSession.play_move` extended to support both `movetime_ms` and full clock parameters (`wtime`, `btime`, `winc`, `binc`, `movestogo`), computing safe move deadlines including padding.
