## 2. Phase 1 — Baseline Audit and Statistical Reconciliations

### 2.1 Audit of the Primary 0/100 Benchmark Claim
In v0.38, the primary benchmark against unrestricted Stockfish 19 yielded 0 wins, 0 draws, and 100 losses (0.0/100 points). The historical report stated a 95% confidence interval of $[0.0\%, 0.0\%]$.

**Independent Re-Analysis:**
A zero-width interval for an empirical sample of $n=100$ is mathematically erroneous:
- Observed sample proportion: $\hat{p} = 0.000$ (0.0%).
- Standard error estimate: $SE = \sqrt{\hat{p}(1-\hat{p})/n} = 0$, but standard Wald formulas collapse at sample extremes.
- Exact Clopper-Pearson (Binomial exact) 95% interval:
  $$[\text{Beta}^{-1}(0.025; 0, 101), \text{Beta}^{-1}(0.975; 1, 100)] = [0.0000, 0.0362] \implies [0.00\%, 3.62\%]$$
- Wilson Score Interval: $[0.0000, 0.0369] \implies [0.00\%, 3.69\%]$.
- Hanley & Lippman-Hand "Rule of Three" Upper Bound:
  $$p_{\text{upper}} \approx \frac{3}{n} = \frac{3}{100} = 3.00\%$$
- **Finding:** The true underlying expected score of Janus against unrestricted Stockfish 19 at $3\text{s}+100\text{ms}$ is bounded between 0.00% and 3.62% with 95% confidence, not identically zero.

## 3. Phase 2 — Quiescence Search Correctness (Candidate Q0)

### 3.1 Defect Discovery in Check-Evasion Handling
Inspection of `_quiescence` in `src/janus/search.py` revealed a severe alpha-beta fail-low defect:
```python
# Unpatched v0.38 search.py
if in_check and not moves:
    return -MATE_SCORE + ply

best_score = -INF if in_check else alpha
for move in moves:
    board.push(move)
    score = -self._quiescence(board, -beta, -alpha, ply + 1)
    board.pop()
    if score > best_score:
        best_score = score
    alpha = max(alpha, score)
    if alpha >= beta:
        break
return alpha  # <-- FATAL BUG: returns alpha even when in_check and best_score < alpha!
```

**Consequences:**
When the engine is in check, `stand_pat` is illegal. If all evasions fail low (e.g. against $\alpha = 0$, every legal evasion loses material or leads to checkmate scoring $< 0$), the unpatched loop returned `alpha` ($0$) rather than the true negative score! The engine reported an equal score ($0$ cp) for positions where its king was doomed or suffering decisive material loss.

### 3.2 Corrective Implementation
1. **Fail-Low Evacuation Fix:**
   `return best_score if in_check else alpha`
   When in check and all moves score $< \alpha$, the function returns `best_score` (e.g. $-MATE\_SCORE + \text{ply}$ or $-900$ cp), propagating true horizon refutations back to the root.
2. **Fail-Soft Window Clamping:**
   Updated cutoffs to return the actual score (`return score`, `return stand_pat`) rather than hard bounds (`return beta`), preserving sharp tactical bounds.
3. **Bounded Quiescence Ply Ceiling:**
   Added hard ply cap (`qsearch_hard_limit = qsearch_max_ply + 8`) preventing check-evasion runaway trees.
4. **Ordered Root-Move Fallback:**
   Fixed root fallback when the search deadline expires before depth 1 finishes: replaced arbitrary `legal_moves[0]` with `self._ordered_moves(board, None, 0)[0]`, eliminating opening blunders like `f4c7??` (mate in 1).
5. **Selective Check Exploration (Q1):**
   Added bounded checking exploration (`enable_qsearch_checks`, `qsearch_checks_max_ply`) with `qply` tracking.

## 4. Phase 3 — King-Safety Evaluation Audit & Calibration (Candidate K0)

### 4.1 Diagnosis of the King-Safety Discrepancy
The v0.38 loss analysis attributed 33% of blunders to "absent king safety." However, inspection of `src/janus/evaluation.py` revealed that king safety terms were already present and active under `--eval-all`.

**Root Cause:**
The existing implementation only evaluated castled kings residing on specific corner squares:
- White king on `g1` or `h1` (kingside castled)
- White king on `b1` or `c1` (queenside castled)

An uncastled king sitting on $e1$ or $d1$ with open central files received **0 penalty** (delta vs closed file was exactly 0 cp). In games 1–30, Stockfish 19 repeatedly blasted open the $d$- and $e$-files, pinning Janus's uncastled king, while Janus evaluated the central exposure with zero concern.

### 4.2 Calibrated King-Safety Formulation
Implemented `_compute_king_safety_mg(board, king_sq, color, has_rights)`:
1. **Castled Kings:** Penalizes open/semi-open $f$-files (-16 / -8 cp) and open $a$-files (-12 / -6 cp).
2. **Uncastled Kings on Central Files:**
   - Open $e$-file or $d$-file: **-24 cp** per open file.
   - Semi-open file: **-12 cp** per semi-open file.
   - Stranded uncastled king with lost rights: **-15 cp**.
3. **Tapered Fade:** King-safety penalties are weighted by middlegame phase ($W_{\text{mg}} \in [0, 1]$) and smoothly vanish in endgames as the king centralization bonus takes over.

## 12. Strategic Weakness Analysis & v0.40 Priorities

With tactical horizon check-evasions and uncastled king safety resolved, the diagnostic match logs reveal the next two primary bottlenecks limiting playing strength:
1. **Move Ordering Efficiency in Main Search:**
   - While MVV-LVA orders captures effectively, non-capture quiet moves currently rely on basic killer moves and history counters. Tuning history heuristic increments and adding countermove heuristics will increase alpha-beta cutoff efficiency.
2. **Static Evaluation Pruning (Reverse Futility Pruning):**
   - In quiet positions where the static evaluation exceeds $\beta$ by a significant margin (e.g. $+150$ cp at depth 1-2), early cutoffs can save substantial search nodes, allowing Janus to reach depth 4-5 within blitz constraints.
