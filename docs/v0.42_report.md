## 3. Phase C — RFP Implementation & Configuration Audit

The RFP implementation in [`src/janus/search.py`](file:///e:/ChessXML/project-janus/src/janus/search.py) (lines 812–828) was forensically audited:

```python
# Reverse Futility Pruning (RFP / Static Null Move Pruning)
if (
    self.enable_rfp
    and ply > 0
    and not in_check
    and depth <= self.rfp_max_depth
    and abs(beta) < MATE_THRESHOLD
    and abs(alpha) < MATE_THRESHOLD
    and board.halfmove_clock < 140
):
    self.rfp_considered += 1
    static_eval = evaluate_side_to_move(board, config=self.eval_config)
    rfp_margin = self.rfp_margin_per_depth * depth
    if static_eval - rfp_margin >= beta:
        self.rfp_cutoffs += 1
        self._store_tt(key, depth, beta, "lower", tt_move, ply)
        return beta, []
```

### Forensic Findings
1. **Safety Guards Verified:** In-check bypass, root bypass (`ply > 0`), frontier depth restriction (`depth <= 2`), mate-proximity guards on both `alpha` and `beta`, and draw-proximity protection (`halfmove_clock < 140`) are actively enforced.
2. **Fail-Hard Semantics:** The search returns `beta` rather than `static_eval - margin`, providing clean fail-hard bounds that prevent search instability.
3. **Configuration Isolation:** In `scripts/match_v040_experiments.py`, Candidate K0 and Candidate RFP differ solely by the `--enable-rfp` flag. All time allocation, evaluation heuristics, transposition table sizes, and quiescence parameters are identical.

## 4. Phase D — Draw Rule Semantics Audit

### 4.1 FIDE Chess Draw Rules in Janus
- **Automatic Draws:**
  - 75-Move Rule (`halfmove_clock >= 150`): Mandated draw under Article 9.6.2. Enforced via `board.is_seventyfive_moves()`.
  - Fivefold Repetition: Mandated draw under Article 9.6.1. Enforced via `board.is_fivefold_repetition()`.
  - Insufficient Material: Automatic draw under Article 9.6. Enforced via `board.is_insufficient_material()`.
- **Claimable Draws:**
  - 50-Move Rule (`halfmove_clock >= 100`): Article 9.3 requires a player claim. Correctly omitted from automatic engine evaluation.
  - Threefold Repetition: Article 9.2 requires a player claim. Modeled at `ply > 0` via `board.is_repetition(3)` to prevent tactical repetition traps while allowing root search (`ply == 0`) to find winning alternatives.

### 4.2 Test Suite Expansion (`tests/test_v042_draw_semantics.py`)
7 targeted regression tests were created and verified:
1. `test_01_seventyfive_moves_in_all_search_contexts`: Confirms score 0 in terminal, quiescence, and negamax.
2. `test_02_fivefold_repetition_triggers_draw`: Confirms automatic fivefold draw detection.
3. `test_03_threefold_at_nonroot_vs_root`: Confirms draw score at ply > 0 while preserving root flexibility.
4. `test_04_fifty_move_rule_not_automatic_draw`: Verifies halfmove_clock = 100 does not falsely trigger automatic draw.
5. `test_05_tt_cutoff_suppressed_near_seventyfive_moves`: Verifies non-zero TT cutoffs are suppressed when `halfmove_clock + depth >= 150`.
6. `test_06_rfp_suppressed_near_draw_threshold`: Confirms RFP is suppressed when `halfmove_clock >= 140`.
7. `test_07_winning_side_avoids_repetition_in_endgame`: Confirms winning positions avoid 3-fold repetition.

## 6. Phase F — Direct Paired Ablation & Causal Attribution

### 6.1 Experimental Protocol
- **Sample:** 25 curated colour-reversed opening pairs (50 games per engine, 100 games total).
- **Control:** Baseline K0 (`analysis/v0.39/match_q0_k0`).
- **Treatment:** Candidate RFP (`analysis/v0.41/match_rfp`).
- **Opponent:** Stockfish 19 (`UCI_Elo=1320`, 1 thread, 64MB).
- **Time Control:** 3000 ms + 100 ms Fischer increment (`arm_c` time policy).

### 6.2 Empirical Results
- **Baseline K0 Score:** 22.5 / 50.0 (45.0%)
- **Candidate RFP Score:** 37.0 / 50.0 (74.0%)
- **Net Point Delta:** $+14.5\text{ points}$
- **Mean Paired Delta:** $\mathbf{\bar{\Delta} = +0.5800\text{ points/pair}}$ ($\mathbf{+29.0\%\text{ per game}}$)
- **Standard Error:** $\text{SE} = 0.2095$
- **Student's $t$-statistic:** $\mathbf{t = 2.7682}$ (df = 24)
- **One-tailed $p$-value:** $\mathbf{p = 0.005345}$ ($p < 0.01$)
- **Two-tailed $p$-value:** $\mathbf{p = 0.010690}$ ($p < 0.05$)
- **10,000-resample Bootstrap 95% CI:** $\mathbf{[+9.0\%, +49.0\%]\text{ per game}}$
- **Pair Performance Distribution:**
  - RFP strictly better: 17 / 25 pairs (68.0%)
  - Tied: 7 / 25 pairs (28.0%)
  - K0 strictly better: 1 / 25 pairs (4.0%)

The null hypothesis ($H_0: \mu_\Delta \le 0$) is **decisively rejected**. The strength gain is causally attributable to RFP.
