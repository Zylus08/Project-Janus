## 2. Inherited v0.50 Audit & Gap Remediation (Phase A)

The v0.50 prototype demonstrated that native C++ move generation and alpha-beta search delivered an order-of-magnitude throughput speedup ($19.4\times$ to $51.3\times$). However, v0.50 withheld Category A promotion due to four critical architectural omissions:

1. **Absence of Game History & In-Tree Repetition:** v0.50 tracked only `halfmove_clock` for the 50-move rule; repetition across game plies and search tree branches was unmonitored.
2. **TT Mate Score Normalization Gap:** Transposition table entries stored raw search values without adjusting mate scores relative to the current search ply ($score \pm ply$), creating potential mate cycle blunders in deeper searches.
3. **Missing Standalone UCI Executable:** N2 existed solely as a shared library (`.dll`) invoked via Python `ctypes`, incurring boundary overhead and preventing standalone GUI or match harness integration.
4. **PV Line Tracking Incomplete:** v0.50 returned only single best moves without extracting principal variations (PVs).

Milestone v0.51 successfully remediated every gap:
- Added `g_game_history[1024]` and in-tree history checking.
- Implemented `score_to_tt` and `score_from_tt` mate normalization functions.
- Implemented a complete, unbuffered native UCI loop and built `janus_native_engine.exe`.
- Implemented triangular PV table tracking (`g_pv_table[MAX_SEARCH_PLY][MAX_SEARCH_PLY]`).

## 3. Normative FIDE Draw Semantics & Repetition Engine (Phase B)

To ensure competitive tournament integrity, N2 was outfitted with comprehensive FIDE draw semantics:

1. **Game History Stack:** A dedicated 1,024-ply circular/flat buffer (`g_game_history`) records the Zobrist hash of every board position reached in the actual game.
2. **In-Tree Repetition Detection:** During alpha-beta search, the engine traverses backwards through both the current search tree ply stack and the prior game history up to the `halfmove_clock` boundary. If the current hash occurs once before in the game history or tree, it is evaluated as an immediate draw ($0\text{ cp}$).
3. **Claimable vs Automatic Draws:**
   - **Threefold Repetition:** Detected when the current position matches 2 prior occurrences in the history.
   - **Fivefold Repetition:** Automatic tournament draw enforced when 5 identical positions occur.
   - **50-Move Rule:** Claimable draw when `halfmove_clock >= 100`.
   - **75-Move Rule:** Mandatory automatic draw when `halfmove_clock >= 150`.
   - **Insufficient Material:** Rigorously detects bare kings, $K+N\text{ vs }K$, and $K+B\text{ vs }K$.
4. **Intended-Move Draw Detection:** Evaluates whether an intended candidate move will trigger a threefold repetition or 50-move draw before playing it.

**Validation:** Evaluated via `tests/test_native_draw_semantics.py` across 12 comprehensive test suites comparing native C++ draw queries directly against `python-chess`. **Result: 12/12 tests passed (100% parity, 0.038s).**

## 4. Memory Safety, Bounding & Stress Qualification (Phase C)

Standalone C++ engine binaries must be immune to heap corruption, stack overflow, buffer overrun, and memory leaks. N2 was engineered with strict zero-heap search constraints:

- **Static Array Allocations:**
  - `MAX_MOVES = 256` per ply.
  - `MAX_SEARCH_PLY = 128` depth ceiling.
  - `MAX_GAME_HISTORY = 1024` ply history stack.
  - Transposition table statically sized to $1,048,576$ entries ($16\text{MB}$ total memory footprint).
- **Hardened FEN Parsing:** Validates piece placements, active color, castling tokens, and strictly checks en passant syntax (rejecting illegal square ranks or malformed tokens).
- **Mate Score Bounds:** Mate scores are normalized to $[\text{SCORE\_MATE} - \text{ply}]$ and clamped within $[-32000, +32000]$.
- **Stress Test Suite (`tests/test_native_memory_safety.py`):**
  - Rapid position replacement (50 cycles with no leaks).
  - Rapid `ucinewgame` reset cycles (50 cycles verifying clean TT wipes).
  - Deep search on extreme tactical positions (Kiwipete to Depth 6).
  - Buffer saturation test (1,200 consecutive history pushes safely clamped without overflow).
  - Hostile input handling (malformed FENs, invalid move strings rejected cleanly without crashing).

**Result: 8/8 memory safety tests passed (0.174s).**

## 5. Search Semantics & Differential Reliability (Phase D)

Search semantics and move ordering were audited across both the inherited 37-position diagnostic corpus and a new 16-position independent validation corpus:

- **Move Ordering Pipeline:**
  1. Hash Move (from Transposition Table).
  2. Winning & Equal Captures (MVV-LVA scored $10000 + \text{victim}\times 10 - \text{attacker}$).
  3. Killer Move 1 ($9000$).
  4. Killer Move 2 ($8000$).
  5. Quiet Moves ordered by History Heuristic score ($0$ to $7999$).
  6. Losing Captures.
- **Root Symmetries & Tie-Breaking:** In positions with identical evaluation scores among quiet moves (common at low depths), Python K0 and Native N2 enumerate legal moves in different order (bitboard square scan vs `python-chess` square scan), which accounts for natural move divergences that resolve as search depth deepens.
- **Differential Throughput (37 Diagnostic Positions):**
  - **Depth 1:** N2 $21.7\times$ faster (871k NPS vs 26.7k NPS, move agreement 43.2%)
  - **Depth 2:** N2 $34.2\times$ faster (757k NPS vs 22.1k NPS, move agreement 59.5%)
  - **Depth 3:** N2 $37.5\times$ faster (318k NPS vs 8.5k NPS, move agreement 64.9%)
  - **Depth 4:** N2 $42.1\times$ faster (163k NPS vs 3.9k NPS, move agreement 70.3%)
  - **Depth 5:** N2 $26.3\times$ faster (149k NPS vs 5.7k NPS, move agreement 78.4%)
- **Validation Corpus (16 Positions):**
  - Speedups ranged from $21.1\times$ (Depth 1) to $71.1\times$ (Depth 4).
  - 100% agreement on forced checkmate announcements and stalemate avoidances.

## 6. Standalone Native UCI Engine Integration (Phase E)

The standalone executable `analysis/v0.51/native/janus_native_engine.exe` was compiled with MSVC 2022 x64 (`/O2 /W3 /std:c++17 /EHsc`):

- **Unbuffered Pipe I/O:** Standard Windows C runtime pipe buffering deadlocks `subprocess` communication when buffering 4KB blocks. N2 enforces `setvbuf(stdout, NULL, _IONBF, 0)` and `std::cout << std::unitbuf` at process startup, guaranteeing instant transmission of every character.
- **Full UCI Protocol Compliance:** Supports `uci`, `isready`, `ucinewgame`, `position startpos/fen [moves]`, `go depth/movetime/wtime/btime/winc/binc`, `stop`, and `quit`.
- **Fischer Time Management:** Computes target move budget via:
  $$T_{\text{alloc}} = \frac{T_{\text{remaining}} + 40 \times T_{\text{increment}}}{40}$$
  Clamped strictly to avoid time forfeiture: $T_{\text{alloc}} \le T_{\text{remaining}} - 50\text{ms}$.
- **Node-Polling Clock Check:** Checks elapsed time every 2,048 nodes to terminate search cleanly between iterations without latency spikes.

**Qualification (`tests/test_native_uci_protocol.py`): 10/10 tests passed (1.055s), verifying 10-ply self-play, handshake, clock parsing, and clean termination.**
