## 3. Search Architecture & PVS Design Specification (Phases 1 & 2)

### 3.1 The PVS Null-Window Principle
In standard alpha-beta, all legal moves are searched with the full window $[\alpha, \beta]$. If move ordering is effective, the first move searched is usually the best move and raises $\alpha$. Subsequent moves are expected to fail low ($score \le \alpha$). Searching them with a full window is computationally wasteful.

PVS exploits this by searching moves after the first with a minimal null window:
$$[-\alpha - 1, -\alpha]$$

If the move fails low ($score \le \alpha$), the cutoff is proved with minimum tree traversal. If the move scores higher than $\alpha$ ($score > \alpha$), the hypothesis that the move was inferior is refuted, and the move must be re-searched with the full window $[-\beta, -\alpha]$ to establish its exact minimax value.

### 3.2 Integrated 3-Tier PVS + LMR Hierarchy
When PVS is composed with Late Move Reductions (LMR), child moves execute within a 3-tier hierarchy:

1. **Tier 1 — Reduced Null-Window Probe (LMR + PVS):**
   If a move is eligible for LMR (quiet, non-checking, move rank $\ge 4$, depth $\ge 3$), it is searched with reduced depth $d - 1$ and null window $[-\alpha - 1, -\alpha]$.
2. **Tier 2 — Full-Depth Null-Window Verification:**
   If Tier 1 fails high ($score > \alpha$), the reduction is refuted. The move is re-searched at full nominal depth $d$, but still with the null window $[-\alpha - 1, -\alpha]$.
3. **Tier 3 — Full-Depth Full-Window Re-Search:**
   If the full-depth null-window search also exceeds $\alpha$, and $score < \beta$, the move is a genuine PV candidate. It is re-searched at full depth $d$ with the wide window $[-\beta, -\alpha]$.

- Default `UsePVS=false` matching N3 baseline behavior.
- UCI options parsing and runtime toggling.
- First move searched with full window $[-\beta, -\alpha]$.
- Subsequent moves searched with null window $[-\alpha - 1, -\alpha]$.
- Correct re-search triggering on alpha improvement.
- Exact minimax score invariance between PVS and full-window alpha-beta.
- Repetition detection and TT transposition table consistency.
**Result:** 30/30 tests passed cleanly in 0.22s.

## 9. Final Release Decision (Phase 9)

**Verdict:** **CATEGORY B — Search-Efficiency Qualified, Strength-Neutral / Codebase Integration with Baseline Default Retained (`UsePVS=false`)**

### Rationale:
1. PVS demonstrates verified mathematical correctness and 100% decision agreement with baseline alpha-beta.
2. PVS delivers measurable tree pruning (up to 13.2% in pure PVS, 9.9% compound over LMR) and a 1.21x speedup at Depth 6, with an ultra-low re-search rate (<0.08%).
3. Under Fischer 3.0s + 100ms, playing strength is statistically indistinguishable from baseline ($p = 0.5663$, 95% CI encompasses zero).
4. In strict accordance with Project Janus governance, only Category A authorizes changing production defaults. Therefore, the production default remains `UsePVS=false`.
5. PVS is retained as a fully supported, production-quality native UCI option (`option name UsePVS type check default false`), laying the essential window-search foundation for upcoming algorithmic features.
