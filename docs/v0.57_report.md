## 5. Machine Learning Integration Design

Full documentation: [`analysis/v0.57/NEURAL_INTEGRATION_DESIGN.md`](file:///E:/ChessXML/project-janus/analysis/v0.57/NEURAL_INTEGRATION_DESIGN.md).

### 5.1 Chosen Architecture: Option B (Neural Move Policy Ordering)
We recommend **Option B** for the first Janus ML prototype (v0.58) because:
- **Zero Tactical Risk:** Move ordering changes only the exploration sequence, preserving 100% alpha-beta correctness.
- **CPU Manageability:** Evaluated only at internal nodes (~50,000 calls/sec vs 1,600,000 calls/sec for leaf evaluation).
- **Training Ground Truth:** Grandmaster game databases provide abundant, clean (FEN $\to$ move) supervision.

### 5.2 Mandatory Tensor Interface:
- **Tensor Shape:** $[1, 14, 8, 8]$ flat 896 floats.
- **Channels 0–5:** White pieces ($P, N, B, R, Q, K$).
- **Channels 6–11:** Black pieces ($P, N, B, R, Q, K$).
- **Channel 12:** Side to move ($1.0$ if White, $0.0$ if Black).
- **Channel 13:** Auxiliary state (castling rights, en passant, halfmove counter).
- **Perspective Canonicalization:** White-oriented; board flipped vertically if Black to move.
- **Output:** Softmax vector over legal moves indexed by $\text{from\_sq} \times 64 + \text{to\_sq}$.
