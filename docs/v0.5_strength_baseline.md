# Project Janus — v0.5 Controlled Playing-Strength Baseline

## 1. Overview & Evaluation Objective

The objective of the v0.5 evaluation protocol is to establish a reproducible, statistically defensible playing-strength baseline for Project Janus against Stockfish 19 under strictly controlled, auditable conditions prior to introducing search or evaluation optimizations.

### Key Principles
1. **Paired Opening Parity:** Every opening position is played twice in succession—once with Janus as White, and once with Janus as Black. Any opening advantage or disadvantage is mirrored across the pair.
2. **Game State Isolation:** Transposition tables and internal search states are flushed between games via standard UCI `ucinewgame` protocol triggers (`game=game_number`).
3. **Hardware-Invariant Horizons:** Fixed-depth limiting (`--depth 3`) isolates algorithmic horizon effects from CPU architecture, clock throttling, and Python-versus-C++ speed disparities.
4. **Resilient Artifact Preservation:** PGN moves are flushed after every game, and summary CSV/JSON reports are safely written even if a match is interrupted by an engine fault.
5. **No Speculative Rating Inflation:** Small samples (e.g. 2–4 games) are reported strictly as protocol verifications; Elo ratings or strength claims are explicitly prohibited without calibrated peer opponents and large sample sizes (100+ games).

## 2. Opponent Selection & Search Limit Analysis

### Opponent: Stockfish 19
- **Binary:** `E:\ChessXML\tools\stockfish\stockfish.exe`
- **Configuration:** 1 Thread, 128 MB Hash.
- **Calibration Limitations:** Stockfish 19 utilizes a deep neural network evaluation (NNUE) and highly optimized C++ search routines. Even at fixed depth 3, Stockfish possesses profound positional and tactical pattern recognition that heavily outclasses a pure-Python hand-crafted evaluation (material + piece-square tables). Stockfish serves as an upper ceiling and correctness validator, not a peer-calibrated peer.

### Search Limiting Trade-offs
| Limit Paradigm | Mechanism | Advantages | Disadvantages |
|---|---|---|---|
| **Fixed Depth (`--depth 3`) [Selected]** | `Limit(depth=3)` sent as `go depth 3` | Completely hardware-invariant; eliminates wall-clock variations; identical search horizon for both engines. | Asymmetric node counts: Stockfish evaluates ~1,000–5,000 nodes in 2ms, whereas Janus evaluates ~100–500 nodes in 50–150ms. |
| **Fixed Movetime (`--time`)** | `Limit(time=T)` sent as `go movetime <ms>` | Simulates clock-based tournament play. | Severe compute disparity: compiled C++ Stockfish searches ~1M nodes/sec (reaching depth 12+), while pure-Python Janus searches ~1k nodes/sec (reaching depth 2–3). |
| **Fixed Node Limit (`--nodes`)** | `Limit(nodes=N)` sent as `go nodes N` | Equates raw evaluation counts. | Not supported by Janus's current UCI implementation (`src/janus/uci.py`). Modifying engine code is prohibited in this milestone. |

## 3. Experiment Configuration & Schema

### CLI Interface (`scripts/match.py`)
```bash
python scripts/match.py \
  --stockfish <path-to-stockfish.exe> \
  --games <even-count> \
  --depth 3 \
  --openings benchmarks/openings.json \
  --seed 42 \
  --stockfish-threads 1 \
  --stockfish-hash 128 \
  --out match-results
```

### Paired Opening Suite (`benchmarks/openings.json`)
The suite consists of 50 diverse, standard opening positions generated by legal move replays across classic ECO codes (e.g. Sicilian, Ruy Lopez, French, Caro-Kann, Queen's Gambit, Indian Defenses, Reti, English).
- When `--games G` is passed, $P = G / 2$ opening pairs are sampled deterministically using `--seed`.
- Round $2k - 1$: Opening $k$, Janus White vs Stockfish Black.
- Round $2k$: Opening $k$, Stockfish White vs Janus Black.

### Output Formats
1. **PGN (`.pgn`):** Full move transcripts with standard headers (`Event`, `Round`, `White`, `Black`, `Result`, `TimeControl`, `Opening`, `FEN`, `SetUp`, `Termination`).
2. **CSV (`.csv`):** Tabular per-game records with columns:
   `game, pair, opening_id, janus_color, white, black, result, termination, plies, depth, start_fen`
3. **JSON (`.json`):** Full machine-readable report containing experiment `metadata`, `summary` (total, completed, W/D/L, percentage, color breakdown), and `games` details.

## 4. Pilot Validation (2 Games, Pair 1)

A pilot match was executed to validate the updated harness:
- **Command:** `.venv\Scripts\python.exe scripts/match.py --stockfish E:\ChessXML\tools\stockfish\stockfish.exe --games 2 --depth 3 --openings benchmarks/openings.json --seed 42`
- **Opening:** `scotch_game` (1.e4 e5 2.Nf3 Nc6 3.d4)
- **Game 1 (Pair 1, Janus White):** Draw (`1/2-1/2`) via threefold repetition (155 plies).
- **Game 2 (Pair 1, Janus Black):** Loss (`0-1` / Stockfish `1-0`) via checkmate (45 plies).
- **Janus Score:** 0.5 / 2.0 (25.0%)
- **Elapsed Time:** 34.2 seconds (average 17.1 seconds / game).

### Integrity Verifications
1. **PGN Legality:** All moves were parsed and replayed using `chess.pgn` with zero illegal moves.
2. **Cross-Artifact Consistency:** Results, terminations, plies, and opening identifiers matched identically across PGN, CSV, and JSON.
3. **Metadata Completeness:** Random seed (`42`), openings path, thread count (`1`), hash (`128`), and search limits were recorded in report metadata.
