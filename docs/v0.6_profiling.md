## 3. Profiling Analysis & Identified Hotspots

Profiling `open_game` at depth 4 with `cProfile` (36,336,721 function calls over 68.67s of profiling overhead) revealed three dominant bottlenecks:

```
   ncalls  tottime  percall  cumtime  percall filename:lineno(function)
   9852/4    0.208    0.000   69.981   17.495 search.py:170(_negamax)
62327/7943    1.952    0.000   65.026    0.008 search.py:129(_quiescence)
    38875    1.086    0.000   26.431    0.001 search.py:119(_ordered_moves)
  1429187    3.749    0.000   25.047    0.000 __init__.py:3702(generate_legal_moves)
    55788    0.119    0.000   23.692    0.000 evaluation.py:68(evaluate_side_to_move)
    55788    6.206    0.000   23.573    0.000 evaluation.py:27(evaluate_white)
  1426468    6.536    0.000   12.938    0.000 __init__.py:1819(generate_pseudo_legal_moves)
   127966    0.810    0.000    9.822    0.000 __init__.py:2100(is_stalemate)
    72179    0.489    0.000    9.322    0.000 search.py:83(_terminal_score)
    38875    0.848    0.000    7.712    0.000 {method 'sort' of 'list' objects}
  1134341    1.205    0.000    6.864    0.000 search.py:124(<lambda>)
  1134341    1.948    0.000    5.659    0.000 search.py:95(_move_order_score)
```

1. **Redundant Terminal Checks in Static Evaluation (`evaluate_white`):**
   - In `evaluation.py:27`, `evaluate_white` is documented as `Evaluate a non-terminal position from White's perspective.`
   - However, every evaluation executed `board.is_checkmate()`, `board.is_stalemate()`, `board.is_insufficient_material()`, and `board.is_fivefold_repetition()`.
   - In `python-chess`, `is_stalemate()` calls `generate_legal_moves()` to check if any legal move exists. Calling `is_stalemate()` 127,966 times incurred ~9.82s of legal move generation.
   - Because `_terminal_score` in `JanusSearch` already intercepts terminal positions at the head of `_negamax` and `_quiescence`, repeating these checks inside `evaluate_white` was 100% redundant.

2. **Full Legal Move Generation & Sorting in Quiescence Search (`_quiescence`):**
   - Out of 72,179 nodes in `open_game`, 62,327 (86.3%) were quiescence search nodes.
   - When not in check, quiescence search only evaluates captures and promotions.
   - However, `_quiescence` was calling `self._ordered_moves(board)`. This generated all legal quiet moves (~35 quiet moves per node), evaluated `_move_order_score` on all quiet moves, sorted the full list, and then discarded quiet moves with list comprehension.
   - Over 1.13 million moves were scored and sorted only to be immediately thrown away.
   - Inside `_move_order_score`, the dictionary `values = {chess.PAWN: 100, ...}` was allocated on every single move call (1,134,341 dict allocations).

3. **Evaluation Dynamic Coordinate Arithmetic & Object Allocations:**
   - `_center_bonus(square)` was called 339,405 times, performing floating-point subtraction `abs(file - 3.5)` and `int()` conversions for fixed 64 square coordinates.
   - Iterating `board.pieces(piece_type, color)` allocated 781,032 `SquareSet` wrapper objects.
   - Bishop pair detection used `len(board.pieces(chess.BISHOP, color)) >= 2`, creating two additional `SquareSet` instances per evaluation.

## 4. Implemented Optimizations & Empirical Validation

Each optimization was implemented and validated sequentially in isolation.

### Optimization 1: Remove Redundant Terminal Checks from `evaluate_white`
- **File Changed:** `src/janus/evaluation.py`
- **Rationale & Hypothesis:** Static evaluation is strictly invoked on non-terminal leaves vetted by `_terminal_score`. Removing `is_checkmate()`, `is_stalemate()`, `is_insufficient_material()`, and `is_fivefold_repetition()` from `evaluate_white` eliminates ~55k calls to `generate_legal_moves()` with zero change to chess evaluation semantics.
- **Verification Results:**
  - All 30 unit tests passed.
  - Depth 3 benchmark: 2.015s -> 1.641s (18.6% faster).
  - Depth 4 benchmark: 26.296s -> 9.797s (**2.68x speedup, 62.7% time reduction**).
  - Nodes: 81,655 == 81,655 (100% exact match).
  - Returned moves & scores: 6/6 identical to baseline.
  - Artifact: `benchmark-results/janus-benchmark-20261014-034804.json`.

### Optimization 2: Quiescence Capture/Promotion Generation & Constant MVV/LVA Table
- **File Changed:** `src/janus/search.py`
- **Rationale & Hypothesis:** In `_quiescence`, when not in check, generate only candidate captures and 8th-rank promotions via `board.generate_legal_captures()` and targeted pawn promotion bitmask moves. Only candidate tactical moves are scored and sorted. Replaced per-call dictionary instantiation in `_move_order_score` with module constant `MVV_LVA_PIECE_VALUES`.
- **Verification Results:**
  - All 30 unit tests passed in 7.63s (down from 14.39s).
  - Depth 3 benchmark: 1.641s -> 0.968s (17,432 NPS).
  - Depth 4 benchmark: 9.797s -> 5.469s (**4.81x cumulative speedup vs baseline**).
  - Nodes: 81,655 == 81,655 (100% exact match).
  - Returned moves & scores: 6/6 identical to baseline.
  - Artifact: `benchmark-results/janus-benchmark-20261014-041209.json`.

### Optimization 3: Precomputed Coordinate Lookup Tables & Direct Bitboard Iteration
- **File Changed:** `src/janus/evaluation.py`
- **Rationale & Hypothesis:** Precompute 64-element tuples for `CENTER_BONUS`, `WHITE_PAWN_RANK_BONUS`, and `BLACK_PAWN_RANK_BONUS`. Replace `board.pieces()` iteration with `chess.scan_forward(board.pieces_mask(...))` to eliminate `SquareSet` wrapper allocations. Replace bishop pair length check with hardware popcount `mask.bit_count() >= 2`.
- **Verification Results:**
  - All 30 unit tests passed in 6.55s (down from 14.39s).
  - Depth 3 benchmark: 0.968s -> 0.828s (20,380 NPS).
  - Depth 4 benchmark: 5.469s -> 4.750s (**5.54x cumulative speedup vs baseline**).
  - Nodes: 81,655 == 81,655 (100% exact match).
  - Returned moves & scores: 6/6 identical to baseline.
  - Artifact: `benchmark-results/janus-benchmark-20261014-041443.json`.

## 7. Remaining Limitations & Next Optimization Candidates

1. **`_terminal_score` Stalemate Checks:**
   `is_stalemate()` remains in `_terminal_score` and accounts for ~1.56s across the search. In `_negamax`, legal moves are generated immediately following terminal probing; stalemate and checkmate can be determined from the generated move list when `not moves`, avoiding calling `is_stalemate()` upfront.
2. **Transposition Table Key Computation:**
   Currently `_key(board)` calls `board.fen(en_passant="legal")`, performing string serialization. Replacing this with `board._transposition_key()` (a native Python integer/tuple hash) would eliminate string formatting overhead.
3. **Stand-Pat Delta Pruning in Quiescence:**
   In `_quiescence`, stand-pat cutoff prunes 38% of nodes immediately. Implementing delta pruning (pruning captures that cannot possibly raise alpha even with queen capture value) could safely reduce tree size without altering tactical evaluations.
