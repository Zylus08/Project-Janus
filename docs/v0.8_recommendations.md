## 1. Synthesis of Forensic Evidence & Architectural Analysis

The empirical forensics of the v0.7 50-game baseline (1W, 26D, 23L, 28.0% score) identified three primary systemic deficiencies in Project Janus:

1. **King-Safety Blindness (33.8% of critical moments, 52/154):**  
   Janus has zero dynamic king-safety evaluation. It views pawns solely as material and advancement bonuses (+5 cp/rank), readily vacating its king's pawn shield and opening attack corridors for Stockfish.
2. **Move Ordering Deficiencies (12.3% of critical moments) & Search Inefficiency:**  
   Janus currently relies solely on static MVV/LVA for captures, leaving quiet moves entirely unordered. In non-capturing tactical positions, it frequently searches losing quiet moves before discovering the refutation.
3. **Quiescence Search Bloat & Incomplete Defense (17.5% of critical moments):**  
   Janus evaluates all captures in quiescence search without delta pruning, wasting computational budget exploring hopeless capture lines.

Studying Stockfish 19's source code (`search.cpp`, `movepick.cpp`, `tt.h`) confirmed that modern chess engines achieve high tactical strength not by deeper brute-force iteration alone, but by **targeted move ordering (Killer Heuristics)**, **evaluation king shields**, and **selective search pruning (Delta Pruning)**.

## 3. Deep Blueprint for the Recommended v0.9 Experiment

Consistent with project constraints (*prefer one targeted experiment over a broad rewrite*), we recommend executing **Candidate 1: The Killer Move Heuristic in Alpha-Beta Search** as the primary experiment for Milestone v0.9.

### Experiment Title: Killer Move Heuristic for Alpha-Beta Search
- **Author:** Project Janus Engineering
- **Target Files:** [`src/janus/search.py`](file:///E:/ChessXML/project-janus/src/janus/search.py)
- **Target Branch:** `v0.3-benchmark-harness`

### Falsifiable Hypothesis
> **Hypothesis:** Storing up to two non-capture "killer moves" per search ply that previously caused a $\beta$-cutoff, and prioritizing them immediately after winning captures in `_ordered_moves()`, will increase early $\beta$-cutoffs on quiet refutations. This will reduce total search nodes on tactical benchmark positions by $\ge 15\%$ and improve Janus's depth-4 match score against Stockfish 19 by $\ge 3.0$ percentage points ($>31.0\%$ score).

### Minimal Code Surface
1. **State Initialization in `JanusSearch`:**
   ```python
   # Two killer move slots per ply, up to maximum search depth (e.g. 64 plies)
   self.killers: list[list[Optional[chess.Move]]] = [[None, None] for _ in range(64)]
   ```
2. **Recording Killer Moves upon Beta-Cutoff in `_negamax`:**
   ```python
   if score >= beta:
       if not board.is_capture(move):
           # Store as killer move if not already in slot 0
           if ply < len(self.killers) and self.killers[ply][0] != move:
               self.killers[ply][1] = self.killers[ply][0]
               self.killers[ply][0] = move
       break
   ```
3. **Ordering in `_move_order_score`:**
   - TT Move: `10,000,000`
   - Captures: `1,000,000 + 10 * victim - attacker`
   - Promotions: `800,000 + promo`
   - **Killer 1:** `700,000`
   - **Killer 2:** `600,000`
   - Quiet moves: `0`

### Required Verification Suite
1. **Regression & Safety Tests:**
   - Verify killer moves are reset per root search iteration or per search invocation.
   - Verify move legality: a killer move from a sibling node must be strictly validated against `board.is_legal(move)` before attempting execution.
   - Run existing 30 unit tests (`.venv\Scripts\python.exe -m unittest discover tests -v`).
2. **Benchmarking Invariant:**
   - Execute `scripts/benchmark.py --depth 4`.
   - Node count must drop or search time must decrease compared to the v0.7 baseline (81,655 nodes / 4.75s).
   - Returned best moves must remain legal and score perspectives unchanged.
3. **Controlled Match Experiment:**
   - Run a paired 50-game match against Stockfish 19 at fixed depth 4 under the exact v0.7 conditions (`--games 50 --depth 4 --openings benchmarks/openings.json --seed 42`).
4. **Pass/Fail Criterion:**
   - **Pass:** Janus achieves $\ge 15.5 / 50$ points ($\ge 31.0\%$) and shows zero illegal moves or engine crashes.
   - **Neutral:** Janus scores $13.5\text{--}15.0$ points with verified node reduction.
   - **Fail:** Janus scores $< 13.5$ points ($<27.0\%$) or shows runtime regressions.
5. **Rollback Condition:**
   - If the implementation increases total runtime or reduces score below 26.0%, immediately revert `src/janus/search.py` via `git restore`.
