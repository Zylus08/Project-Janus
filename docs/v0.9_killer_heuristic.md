## 1. Executive Summary & Objective

Milestone **v0.9** introduces a targeted search move-ordering enhancement: the **Killer Move Heuristic** in Janus's alpha-beta search (`src/janus/search.py`).

### Motivation & Hypothesis
In alpha-beta search, the efficiency of subtree pruning depends heavily on finding a cutoff move as early in the move loop as possible. While captures and promotions are effectively prioritized using MVV/LVA, quiet (non-tactical) moves previously shared an identical static score of `0`, leaving them explored in arbitrary legal generation order.

The killer move hypothesis states:
> *A quiet move that produced a beta-cutoff in one branch is very likely to cause a beta-cutoff at sibling nodes at the same search distance from the root (ply).*

By storing up to two quiet refutation moves per ply and scoring them directly beneath promotions but ahead of ordinary quiet moves, Janus should trigger beta-cutoffs earlier in move iterations, cutting down redundant subtree expansions without altering minimax evaluation or move legality.

## 2. Architectural Design & Move Ordering Hierarchy

### Move Ordering Priority
To preserve search correctness and prevent tactical blunders, the move ordering hierarchy maintains strict stratification:

| Priority | Category | Score Range | Description |
| :---: | :--- | :---: | :--- |
| **1** | **TT / Hash Move** | `10,000,000` | Principal variation or prior best move from transposition table |
| **2** | **Winning / Equal Captures** | `980,000 – 1,200,000` | MVV/LVA (`1,000,000 + 10 * victim - attacker`) |
| **3** | **Pawn Promotions** | `800,000 – 800,005` | `800,000 + promotion_piece_type` |
| **4** | **Killer Move 1** | `700,000` | Most recent quiet move causing a beta-cutoff at this ply |
| **5** | **Killer Move 2** | `600,000` | Previous quiet move causing a beta-cutoff at this ply |
| **6** | **Quiet Moves** | `0` | Unordered quiet moves |

### Implementation Constraints & Invariants
1. **Scope:** Purely confined to `src/janus/search.py`. No changes to `src/janus/evaluation.py` or `src/janus/uci.py`.
2. **Quiet-Only Gate:** A move is recorded into killer slots if and only if it causes a beta cutoff (`alpha >= beta`), is not a capture (`not board.is_capture(move)`), and is not a pawn promotion (`move.promotion is None`).
3. **Two-Slot Shift with Duplicate Prevention:**
   When a new killer move arrives at ply $d$:
   - If `move == killers[d][0]`, no shift is performed (slot 0 already holds it).
   - If `move != killers[d][0]`, `killers[d][1] = killers[d][0]` and `killers[d][0] = move`.
4. **Table Lifecycle:**
   - Pre-allocated table of size `max_killers_ply = 64`.
   - Cleared at the beginning of each root `search(board)` call.
   - **Retained across iterative deepening iterations** within the same root search, allowing shallower iterations to seed killers for deeper iterations.
   - Bound-checked on all accesses to guard against ply overflow.
